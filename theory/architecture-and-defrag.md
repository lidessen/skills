# 整体结构、分治与归位

从通用技能方法形成资料整理的公开摘编；不是内部试验原始记录。

相关历史原文及主题重叠见[理论阅读入口](README.md)。

## 先辨认边界，再安排位置

代码、文档、配置和生成物放在哪里，需要先看它们承担什么责任。目录、package、module、构建目标、进程与交付物表达不同关系，不能只凭目录名字判断边界。

结构判断先恢复职责、依赖与 API、构建与版本、运行与交付、状态与资源，以及维护和发布的归属，再选择能够执行和验证的边界。`public/`、`internal/`、`components/` 等名字没有跨语言通用的含义；一个 workspace 或 build target 也不自动意味着独立服务、公开 API 或独立部署。

跨语言项目是否拆仓库，取决于原子提交、依赖隔离、版本治理、发布频率和维护归属。大型项目的构建规则与目录不能按名字照搬；值得吸收的是它怎样约束依赖、组织评审和承担发布责任。[Parnas 的模块化论文](https://ckrybus.com/static/papers/decomposing_systems_into_modules_1972.pdf)提供了一个出发点：围绕容易变化或需要隐藏的设计决策组织模块，不简单照着执行流程拆分。

## 分出去之前，知道怎样接回来

分治从整体目标和覆盖范围出发，形成有界贡献及其依赖，再通过真实工具派发、根据证据调整，最后检查组合结果。这些关系可以迭代，不要求固定阶段、人数或角色。

分工只传共同核心与必要的相邻关系，局部可以自行探索；公共前提变化时要及时传播。共享目录不能假设写入隔离。调度依据完成证据和依赖释放，不能只看参与者是否忙碌，或等待所有分支同时结束。

协调者保留整体判断，检查关键证据和接合，不重复完成全部子任务。实现审查需要双向核对：实现对象是否得到检查，设计责任是否有真实调用路径承接。局部报告各自成立，不等于组合后的系统成立。

这些判断借鉴了算法中的子问题与合并、系统工程中的集成和控制论中的反馈；开放任务没有排序问题那样固定的规模或证明条件，不能据此计算固定人数、承诺加速比或宣称稳定性。

## 归位时保留有效的使用关系

同一事实可以有多个有效表达。原始规则、面向不同读者的说明、生成产物和历史记录需要先区分；只合并独立竞争的规则来源，对合理视图保留来源及同步关系。例如 API 参考和入门教程可以并存，不应仅因覆盖同一 API 就合成一篇。

删改前，检查会不会改变对象身份、主张强度、适用范围、来源、优先关系、允许行动、失败处理或接受标准。删掉“尚未验证”可能把目标改成事实；合并指导段落可能改变指令作用域。格式检查与普通单元测试未必能覆盖这些变化。

判断单位可以小于文件。旧设计的机制被替代，失败原因仍可能有效。先确认当前规则由谁维护，再决定保留原记录、抽取独有依据或修正入口；历史记录需要不可变时，用新说明指向它，不重写历史。

对重要清理候选，先找最有力的保留理由：哪个调用方、当前决定或历史教训会推翻删除建议？确认失效与尚未发现用途需要分开。发现部分仍有效时，收窄清理对象。来源缺失时查明关系，不把未知当杂物；也不无限延迟已有足够证据支持的取舍。

## 用原来的困难检查结果

先挑一个真实困难，例如确认配置优先级，或找到某项规则的维护处。整理后沿同一任务检查：能否正确找到依据、理解例外、定位修改范围，其他消费者是否失去必要区别。

收益与证据强度分别说明。合并若增加转发层、例外配置或长期同步义务，也要计算这些负担。移动了文件而未减少任何负担，不能算收益已经成立；没有可比基线时，只报告观察，不声称效率提升。

上述方法提供结构与取舍的判断依据，没有证明它们能在所有任务中减少成本或提高正确性。真实使用仍需保留有效行为，并据具体反例调整。

## 文献与方法来源

- [MIT 6.006：归并排序讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)：子问题、基本情况与合并分别有正确性条件。
- [CMU 15-210：算法分析](https://www.cs.cmu.edu/afs/cs/academic/class/15210-s14/www/lectures/analysis.pdf)：总工作量、依赖关键路径与调度开销需要区分。
- [NASA Systems Engineering Handbook：Product Integration](https://www.nasa.gov/reference/5-2-product-integration/)：集成关注子系统及环境之间的相互作用。
- [Ashby：An Introduction to Cybernetics](https://www.ashby.info/Ashby-Introduction-to-Cybernetics.pdf)：反馈与可用响应的关系，不构成对 Agent 工作稳定性的证明。
- [Anthropic：多 Agent 研究系统的构建经验](https://www.anthropic.com/engineering/multi-agent-research-system)：独立方向、委派、上下文与整合的实践参考，研究系统的比例和性能不能直接移植为代码任务标准。
