# 从真实对象提炼设计语言种子

先研究具体对象，再总结语言。本轮选择 Apple 平台界面、Linear 工作区、Material 3
Expressive 与 Figma UI3：它们公开了设计意图、具体表达及适用边界，部分有改版反例。
这是有依据的对象选择，不是本轮测得的流行排名；一个场景也不代表品牌的全部设计。
初查于 2026-10-03；当前版本和后续纠正以[当前设计参考](current-design-references.md)为准。
Apple 已更新到 OS 27，Material 补 2026 指导；Claude 暖编辑归因撤回。此前凭气质编出
的六组分类撤回，不作为成熟种子。旧试作的形式辨识不能替代现行版本核对。

另保留有公开源码依据的 DeepSeek Harness 历史结构参考，范围限定于阅读、
输入与过程回查，当前版本外观未复核。Claude／Codex 生成指导、厂商品牌及 AgentParty 候选的
构建基础与取舍见 [构建基础分析](design-construction-bases.md)，不按名称全部收种子。

Apple／Linear／Material 保留为有现行依据的迁移参考，Figma 保留制作关系与修订反例；
Claude 完整客户端、编辑式手绘与纸面终端等仍为候选。没有一个已获稳定产出或用户
审美验收。内部实验不作为公开效果证据；使用者仍需在自己的任务中检验。
选定后如何形成设计，读[设计决定指引](design-language-guide.md)。

“神”是从对象中提炼的服务价值与组织原则，“形”是承载原则的具体表达，“生长”是
迁移建议。下面不提供品牌皮肤或待导入的组件库，也不把官方意图当迁移效果实证。

## 审美语言与代表样本

参考产品也可以帮助识别可迁移的审美语言，不必以品牌名称命名所有种子。以下是工作
命名，不宣称行业已有统一分类；手绘与暖编辑在这里都是通用构成建议，
不代表某个客户端或已验证的产品案例。完整页面及迁移效果仍需检验。
构建依据见[分析](design-construction-bases.md)。

**编辑式手绘（Editorial Doodle），通用构成建议。** 黑墨轮廓、局部不规则线条、
简化人物与猫、少量平涂亮色，配合稳定的无衬线正文和清楚的控件。这种手绘的核心
是有编辑意图的叙事：插画解释谁在做什么、引导进入任务，视觉人格随任务负担退让。
首页可以活泼，填写时安静，管理页优先扫读。迁移时先找到产品的叙事角色，再组织
场景与装饰密度；不要把所有边框画歪、改成手写字体或到处贴吉祥物。硬描边与硬影
只是部分形式，不能单凭它们把整套语言概括为新粗野主义。

**温暖编辑风（Warm Editorial），通用旧试作；撤回 Claude 当前客户端的代表归因。**
暖白／奶油底、近黑文字、陶土强调、富有阅读节奏的排版，常以衬线展示文字搭配实用
正文。公开 frontend-design 确实列出了这一常见组合，但它不是当前客户端外观依据。
当前 Claude 的正常会话与桌面完整新版画面仍待核实，不以该组合填补。
这里提炼的是一种可辨认的语言家族：用纸面阅读感、克制层级和温和强调营造思考与
交谈的气质。该气质是设计解释，不是已测得的信任提升。迁移时让长文本、结果和
行动形成清楚的阅读节奏，按内容选择字体角色；不要只把背景染米色，或让暖色、
低对比和衬线妨碍密集操作。品牌 skill 的字体不能直接充当 Claude App 字体证据。

两个种子都可以亲切，但表达机制不同：编辑式手绘靠角色与场景叙事，温暖编辑风靠
阅读、字级和语气。试作应检验这些关系，不仅比较配色。候选状态表示效果待检验，
不意味着否认可辨认的风格本身。

## 选择起点

| 对象与研究范围                         | 核心关系                                 | 适用起点                       | 容易借错的形                     |
| -------------------------------------- | ---------------------------------------- | ------------------------------ | -------------------------------- |
| Apple 平台界面，OS 27 现行修订         | 内容主导，功能层清楚，操作与空间关系连续 | 内容浏览、跨尺寸导航与直接操作 | 全页玻璃、统一大圆角、仅静态模仿 |
| Linear 工作区，2026 refresh 与现行参考 | 保持工作密度，稳定定位，按职责分配注意   | 多视图任务与属性比较           | 灰紫暗色、小字、全部低对比       |
| Material 3 Expressive，含 2026 更新    | 情绪表达与关键动作识别共同设计           | 主动作、分组与情绪连接         | 满屏彩色、任意形状、破坏熟悉操作 |
| Figma UI3；品牌另分析                  | 作品居中，工具可达，熟练工作不断裂       | 制作对象、编辑器与属性检查     | 品牌海报或悬浮面板直接套工作台   |
| DeepSeek Harness 客户端，固定源码版本  | 阅读、输入与过程回查相接，辅助区域分工   | Agent 对话工作台与设置         | 灰白圆角皮肤、照抄会话业务       |

先匹配内容、行为、期望气质及项目约束。已有有效语言时沿用，不因种子重新改版。
产品与宣传、原生与 Web、不同年代分别核对；需要更多细节时回到具体对象与来源，
不只根据名称生成。以下提炼名称不宣称是品牌的官方流派名。

## Apple：内容、功能层与连续操作

**为何选。** 当前以[WWDC26 修订](https://developer.apple.com/videos/play/wwdc2026/102/)
和 [OS 27 设计资源](https://developer.apple.com/design/resources/)为主，WWDC25 说明只解释
体系起源；[HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
区分内容与控制／导航层。对象是平台界面，不从 Apple 产品广告推导日常操作。

**神。** 内容是用户来使用的对象，工具帮助行动而不遮蔽对象；几何、层级和变化让
人理解所在位置、正在操作的对象及结果来源。跨尺寸与状态仍保持这些关系，才能形成
完整感，不能简化为白色、留白或玻璃。

**形怎样承载神。** 新体系协调嵌套曲率、边距与比例，而非所有圆角同值；保留光学
偏移，触屏胶囊与密集桌面的圆角矩形按用途分工。提醒与引导中的较强字重、左对齐
加强阅读结构；展开的操作与触发来源相接，布局和分组建立层级。这些具体关系见
[体系说明](https://developer.apple.com/videos/play/wwdc2025/356/)。

Liquid Glass 给导航与控制一个可区分的功能层；[材质指导](https://developer.apple.com/design/human-interface-guidelines/materials)
限制它进入内容层并要求克制。[材质演讲](https://developer.apple.com/videos/play/wwdc2025/219/)
将运动、环境适应与可读性一起设计。单个 CSS 模糊背景不具备这套组合行为。

**怎样生长。** 在内容页划清阅读面、导航与临时操作，先制作触发、展开、返回之间
的关系，再协调字级、形状与表面。Web 可用实色与较轻过渡承载原则，保留自身品牌。
圆角、透明度和运动不是任意组合的独立旋钮。

**反例与边界。** 正文也做玻璃、叠玻璃、全部动作同等着色，会破坏层级，官方已有
反例。变化若使人追不住操作对象，漂亮单帧也不成立。迁移后另检查真实内容、窄屏及
减少动态／透明度的表达；原生框架的保障不自动存在于 Web。

## Linear：密集工作中的稳定与退让

**为何选。** [2024 重设计](https://linear.app/now/how-we-redesigned-the-linear-ui)
和 [2026 更新](https://linear.app/now/behind-the-latest-design-refresh) 说明结构及具体修订，
能分析功能增长怎样破坏一致性。研究工作区，不是营销首页。

**神。** 事项与推进关系可定位、可比较、可行动。保持丰富密度，同时让完成定位的
导航退让；同类动作不能随视图漂移。

**形怎样承载神。** 2026 更新分配工作内容与导航的视觉重量，收减多余图标、边界
及装饰，恢复头部动作的可预测位置。官方对照图中选中项仍明确，非活动项退让，图标
尺度与组间距同时变化；这是注意关系的修改，不是全页一起调灰。
见[更新说明及前后图](https://linear.app/now/behind-the-latest-design-refresh)。

**怎样生长。** 在列表、详情与另一种实际视图中固定位置／视图／动作的职责，保留
必要属性与状态的扫读关系，再减少外围竞争。明暗、字体、强调色可变，任务主次与
定位不能丢。密度由真实操作决定。

**反例与边界。** 小字、弱化所有文字或低密度大卡片都不自然产生这种语言。官方
自定义主题与改版也反证某个灰紫色不是本质。边界变弱必须以归属仍清楚为前提；
学习引导与长文阅读不能机械套用高频工作区密度。

## Material 3 Expressive：表达帮助看见关键动作

当前制作还须读[2026 更新与现行案例](current-design-references.md#material现行-expressive包含-2026-更新)：
scaffold、跨设备布局及文字系统高度等已更新。下面 2025 研究解释原则，不能单独代表
最新完整形式；旧发布时间的组件也可能仍是现行指导，不能为“最新”擅改历史日期。

**为何选。** [Google 官方研究](https://design.google/library/expressive-material-design-google-research)
给出成功案例和失败反例。其报告支持特定案例，不能直接外推成本项目的效果。

**神。** 情绪表达与功能识别一起设计；色彩、尺寸、形状和分组帮助辨认重要对象
与动作，不给全部控件添加同等兴奋感。

**形怎样承载神。** 邮件案例把发送放在与输入相邻的位置，协调尺寸、色彩与容器。
实际案例图仍保留正文、工具和输入区的稳定分组；鲜明表达不要求每个元素都特殊。

**怎样生长。** 先确定关键动作，再让位置、尺度、轮廓和颜色共同支持它，辅助动作
可辨而退让。表达强度根据任务和品牌改变，不照抄案例配色或把所有按钮做成焦点。

**反例与边界。** 官方无序专辑图片方案虽被认为新颖，却损害播放列表识别；去掉
动作文字也伤害使用。保留熟悉结构与必要标签，金融和密集工作另作取舍，不能预设
所有用户都偏好强表达。本节案例与反例见[官方研究](https://design.google/library/expressive-material-design-google-research)。

## Figma：作品主导，工具帮助制作

保留制作关系参考；现行完整工具／属性状态与连续制作效果尚未核实，不提供 UI3 完整外观规范。

**为何选。** [UI3 初始方案](https://www.figma.com/blog/behind-our-redesign-ui3/)
与 [反馈修订](https://www.figma.com/blog/our-approach-to-designing-ui3/) 留下漂亮方案失效的
记录，能判断服务价值为何要求改变形式。

**神。** 用户作品在中心，工具随制作对象组织；新人能理解，熟练者能连续操作。
清爽要与工具识别、可达和工作空间同时成立。

**形怎样承载神。** 画布、文件／图层导航与属性面板分工；输入背景、下拉边界、
图标与完整标签区分控制。悬浮侧栏曾挤占小屏画布、干扰工作，后来收回；标签也因
可访问性问题调整。见[修订说明](https://www.figma.com/blog/our-approach-to-designing-ui3/)。
保住内在价值可以要求舍弃已发布形式。

**品牌与工作区的区别。** [品牌语言](https://www.figma.com/blog/figma-on-figma-evolving-our-visual-language/)
用可选择、组合和变换的几何物件表达共同制作。它启发创作入口与叙事，不能推出属性
表单也应大色块和混合字体。活跃品牌与克制工作台服务不同角色。

**怎样生长。** 把工具与当前对象、反馈和作品空间连起来；控制区可换主题与轮廓，
不隐藏必要标签。宣传区借制作关系表达参与，工作区仍保持稳定定位。五色图形没有
制作关系，只是标识模仿。

**反例与边界。** 不为悬浮美感增加命中负担，不从海报推导工具密度；没有制作对象
的任务页也不用强造画布来接近 Figma。

## DeepSeek Harness：对话阅读、输入与过程回查

以下为固定版本历史结构分析。当前远端变化见[版本边界](current-design-references.md)，
在主题、正常对话与过程回查复核前，不称现行完整语言。

**对象与基础。** 研究的是本地 `deepseek-harness` 的客户端，版本 `639ed015397290b3745d163aafe02ffee4aa3f84`，
不是 DeepSeek 模型生成网页的统一倾向。主题、React primitives 与对话布局共同实现
它的表达；CSS 明确引用上游 deepsuite 变量和设计平台值，不能归于 React 默认样式。
具体源码和证据层次见[构建基础分析](design-construction-bases.md#deepseek-harness)。

**神。** 从实现提炼：连续对话是阅读主轴，输入是持续可用的行动入口，过程与输出
保留回查关系；导航、设置、辅助工具各有职责，不与正文等权。这是对源码关系的解释，
不宣称代表设计团队全部哲学。

**形怎样承载神。** 系统与 CJK 字体承担阅读，品牌字另分角色；中性色面、文字和
边界有语义层级，强调与状态有专用色。输入、对话、队列等沿共同宽度轴线组织；
工具结果使用适合内容的阅读形式，结束过程可展开核查。设置页采用分区导航与信息行，
不将所有页面复制为聊天布局。

**怎样生长。** 对 Agent 工作台先建立阅读—输入—过程／成果的关系，再协调导航、
相关动作与设置。保留宿主的会话、草稿、权限与运行事实；参考项目有会话列表，不意味着
另一个产品必须新增会话业务。宽度、控件尺度和圆角按消费者改变，而非抄整份数值。

**反例与边界。** 仅抄灰白背景、圆角输入框和蓝色仍缺内容组织；只展示最终答案又
去掉必要过程与来源，也丢失回查关系。密集表格、长文出版或品牌营销需要自己的构图。
原生 macOS 材质不自动由 Web 复现，不能用阴影声称平台效果相同。

以上关系由公开源码提供结构参考，不证明当前画面或跨项目效果已经确认。

## 使用与继续提炼

### 从组织原则到可辨的表达

从组织原则到可辨表达时，Apple／Linear 可能退化成普通侧栏和表单，
Material 也可能只剩紫色与大圆角。以下是针对这些风险的制作线索，
不是官方 token，也不是通用界面的统一参数。其效果仍需实际试作。

- **Apple 平台界面**：先明确所借的平台与界面类别，再协调工具条、分段选择、侧栏
  选中态、内容字级和控件曲率。控制区域可成为轻、紧凑且与内容区区分的表面；正文
  保持稳定实底。不要用巨大的圆角外壳替代所有内部关系。需要层连续性时，让来源
  展开与触发位置相接；Web 的浅色、轻影或透明控制面只能作为近似，不能宣称原生
  材质复现。回到上文官方演讲中的完整场景核对，不只看单个按钮。
- **Linear 工作区**：位置／视图／动作形成紧凑、可预测的头部，比较用的资料属性
  在主体中有稳定的行列关系；侧栏承担定位而非全部资料展示。详情或记录操作按
  当前对象相接。用适度字级、低竞争导航和较少分隔共同建立密度，不只换灰紫色。
  可依据[官方头部与改版对照](https://linear.app/now/behind-the-latest-design-refresh)
  核对关系。材料只有三项时保留真实空白，不虚构事项；这种样板不证明大密度表现。
- **Material 3 Expressive**：主动作的容器、尺寸、位置和形状共同形成焦点，辅助
  分组可以采用不同但相关的轮廓与色阶。先检验焦点与稳定阅读是否同时成立，再
  借熟悉结构上的局部形变或有因果的运动发展表达；不是所有区域同样放大圆角。
  每处显著形态都要有职责，不能为了“像 Expressive”添加装饰按钮或破坏标题换行。

Figma 还原先确认真实制作对象，不能把只读参考铺成中心纸页、把实际编辑器塞到
边栏来模仿画布。DeepSeek 的持续输入与主轴要结合内容长度，少量摘录不必为固定
底部输入制造大段空白。编辑式手绘和温暖编辑风的识别组合见前文，不能仅据暖底色
把它们与 AgentParty 的等宽、方角、实体按压混为同一纸面风。

选一个主种子，说明任务为何匹配、保留什么核心关系、允许怎样改变形式，再制作
真实主体、辅助区域与相关状态。无需试完全部种子；已有方向不凑候选。混合时交代角色
如何衔接，例如工作列表与阅读说明共享状态语义而使用不同节奏。

检查形神是否相接：当前形式帮助谁理解什么、完成什么？换掉它会损害什么关系，
哪些形可以改变？只剩品牌相似度的，回到对象分析；也不只抄“内容优先”口号，必须
做成字级、几何、分组、状态与过渡的具体表达。

新增种子先说明对象选择，限定年代、平台与产品／品牌范围，核对官方意图和完整案例，
寻找修订或反例，再提出迁移条件。缺证据保留为候选，不为目录齐全补流派。独立试作
决定哪些关系有效，不能靠种子名字直接验收。
