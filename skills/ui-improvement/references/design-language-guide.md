# 将种子发展为一套可执行的设计

在选定语言后使用。本指引把任务关系转成布局、字色形、状态与尺寸的共同选择；
对象依据和版本见[种子](design-language-seeds.md)与[当前参考](current-design-references.md)。
这是迁移指引，尚未经过跨任务稳定性验证，不是品牌复刻规范。

## 从任务确定骨架

控件、信息层次或跳转本身不合理时，先用[交互结构](interaction-structure.md)核对活动，
再进入视觉骨架。风格不能把不适当的select、modal或分步流程包装成合理选择。

先找用户操作的对象、反复发生的行动，以及行动前需要知道什么。选择一个主要阅读／
制作轴线，再放定位、比较、操作、回查与收尾。不要预设每个任务都有侧栏、三个 pane、
一张大卡和一个固定底部输入框；这些结构必须能解释真实需求。

| 任务关系                         | 合适的起点                         | 改变布局的触发                                       |
| -------------------------------- | ---------------------------------- | ---------------------------------------------------- |
| 对多个对象反复比较属性、切换详情 | 稳定列表或表格 + 当前对象详情      | 属性可同屏比较才用表格；长标题与少属性适合列表       |
| 长时间阅读一个对象，再行动       | 连续阅读轴 + 相邻行动，定位退让    | 窄屏可将选择器移至可返回入口，保留对象名称与切换途径 |
| 实际制作／修改一个作品           | 制作对象居中，参考与属性辅助       | 只读材料不是作品；没有制作对象就不强造画布           |
| 顺序填写或理解一项任务           | 引导、必要材料、输入、结果连成顺序 | 回看或分支很多时用稳定步骤定位；不要强迫无关步骤     |

桌面多栏只是同时看多个角色的一种方式。窄屏先判断哪些需要同时出现，哪些可以
切换；长时间阅读可从单 pane 开始，即时对照或批注可能仍需并列辅助区，反复比较可
保留紧凑概览。给切换对象、返回与草稿明确归属，
不能为了短首屏把必要材料删掉。更多留白、更多密度都要由任务解释。

## 让一组形式共同承担职责

先选能区分主体、导航、控制与结果的关系，再协调局部数值。原型可从少量关联选择
开始，不必先写完整 token 系统。

- **字**：标题表达对象或动作，正文保证连续阅读，状态帮助扫读，说明弱于正文但仍
  可读。展示字体只放在有表达职责的位置；中文实际字形、行高与换行须实看。
- **色**：先让前景与背景可读，再分选择、动作和业务状态。当前选择不等于成功，
  不能用一种强调色代替全部状态；错误不能只改变颜色。
- **形与表面**：给同一职责相近轮廓，不同层级可变化；嵌套关系先看内外边距与曲率。
  阴影和透明度表达层次，装饰不能把所有面提升为前景。
- **空间**：同组更近，跨组有节奏，文字与操作有明确归属。先看整屏重量，再看
  图标与文字的光学关系；只有数学等距不足以证明正确。
- **变化**：展开、选择、输入、反馈应能追溯到触发对象。动画用于说明变化，减少动态
  时仍能理解；未实现的动态关系不靠静态截图认证。

若整体趋同，先确认是否损害目标：同一任务可以共享有效骨架。组织成立时，核对
字体角色、表面层次、控件轮廓与强调的关联形式，不必为了差异重排布局。若风格成立而局部不协调，修局部，
无需换种子。若混合语言，按区域职责组合并共用状态意义，不把多套强调系统叠起来。

## 参考工艺对照

用于目标语言已经选定，但实现只有相似外壳、缺少精致感的任务。先找参考中职责相近的
完整页面或区域：阅读对阅读，填写对填写，对象管理对对象管理。聊天页只能证实聊天的
组织，不足以指导全部设置或资料页；没有对应页面时，明确借哪一段关系，其余仍需设计。

保留参考截图与当前基线，注明视口、缩放、主题和状态。尽量用等价长度、数量和角色的
内容比较；不要让参考的短标题、空白状态或精美素材替实现赢得比较。参考无法替换内容时，
先区分内容造成的差异与编排造成的差异，再用项目真实内容检验迁移。

将眼前画面拆成“关系—承载方式—决定性细节”。例如辅助说明弱于输入区，是关系；
通过贴近字段、较小字级和较轻前景实现，是承载方式；实际行高、换行宽度和与下一组的
距离决定它是否安静且清楚。记录能在画面中指出的依据，不以“高级、克制、清晰”代替。
量测可帮助找比例和差值，不能把不同内容、字形和用途强压到相同像素。

按当前最大差异制作，通常从整屏向内收敛：

- **骨架与重量**：主体宽度与起点，导航、标题、内容和动作各占多少注意；哪些区块靠
  排版相连，哪些确实需要容器。先修共同轴线与组间关系，避免在失衡骨架上磨按钮。
- **字与密度**：实际字体及回退字体、字重、字号、行高和行长怎样形成层级；组内紧密
  与组间停顿是否不同。检查中文、长说明和真实标签，不从 CSS 字体名推定已呈现。
- **表面与轮廓**：背景到内容面、输入面与浮层的层级是否清楚；边线的明暗、内外曲率、
  分隔和投影是否共同表达角色。主题色相同而每组都加框，仍可能改变参考的整体语言。
- **局部与变化**：图标的笔画、可见大小与文字的光学对齐，控件内边距、焦点、悬停和
  展开后的邻接关系。稳定初态接近不证明活动时仍精致。

不是每次重做全部层次；上层已经成立就保留，从有证据的缺口进入。每项重要变化说明是
忠实迁移、为业务或平台适配，还是仍缺参考。适配要给出具体约束与视觉代价；不能把
所有偏离归为“允许变化”，也不为复刻造无功能控件或删必要内容。

制作后在一致条件下并排看整屏和关键局部，也回到正常大小实际使用。先说明原差异是否
缩小，再判断是否牺牲了其他关系。若改完只有参数变化却无法指出画面收益，撤回或查
上一层原因；不要靠更多装饰补偿。保留两条结论：任务与动线是否成立，参考语言和工艺
是否到位。前者通过而后者未到位时，仍是待打磨的实现，不以功能验收结束还原工作。

## 各种子的设计决定与反证

### Apple 平台关系：稳定内容，清楚控制层

用于内容浏览和直接操作。先做连续、可读的内容面，再把定位与控制放到可区分的
功能层。字级随内容任务，系统字体与克制强调优先；选中态、嵌套控件与工具条共同
帮助定位，不以巨大窗口曲线替代内部设计。

Web 迁移可以用实底控制面、亮边或轻投影；透明必须有真实背景并保持可读，正文
不做玻璃。滚动、展开和返回保持操作来源，窄屏只留当前所需控制。内容被材质遮盖、
卡片全漂浮或操作来源失踪时，撤回相应形式。不能声称 CSS 具备原生光学保障。

### Linear 工作区关系：稳定定位，丰富内容，外围退让

用于高频对象管理和比较。头部明确位置、当前视图与该视图动作，跨视图相同职责
保持位置；导航降低竞争，主体保留足够清楚的属性、选中态与动作。紧凑无衬线、
暖中性色与少分隔共同服务扫读，不能单凭灰色或小字形成语言。

布局由比较需要决定：少对象不额外造全局工作区；对象属性多时形成稳定行列，长文
详情另用合适阅读宽度。窄屏让比较属性保留身份，可变为每对象分组，不能截掉关键
状态。只有三份资料不能验证密度；如果所有文字都弱、必须猜行归属或导航比任务
更抢眼，先修层次。按内容重做，而不是固定三栏。

### Material 表达关系：熟悉操作骨架，关键动作鲜明

先确定主要动作及其对象，选择 list-detail、feed 或 supporting pane 等任务相符的
组织。bar、rail、pane 不必全部出现；分类不是产品级导航时可以使用局部筛选。
以一组色阶区分背景、分组和选择，按角色变化轮廓与尺度；主动作通过位置、尺寸、
颜色共同清楚，辅助动作保留名称并退让。

正文使用稳定的字级与表面，表现性标题只用于真正需要强调的内容。窄屏选择单 pane
或保留概览须由使用频率决定，返回保留当前对象和草稿；焦点随实际重绘留在合理
位置。若鲜明输入区夺走阅读、各按钮同样突出或陌生形状妨碍辨认，降低表达强度。
Expressive 不等于紫色、大圆角或到处回弹。

### Figma 制作关系：作品占主轴，工具与属性随对象

保留为制作型任务的组织参考；完整当前外观尚待补齐。先找实际编辑对象，制作工具
紧邻工作，定位和属性分别承担导航与检查；只读参考放辅助位置。输入控件、标签、
焦点和选中对象共同说明正在改什么。不能为了模仿工具台发明没有作用的工具栏。
窄屏需要切换辅助面时仍能返回作品，不把参考升为中心、把制作挤到角落。

### 编辑式手绘：角色叙事进入任务，操作区安静

先决定谁在做什么，再用原创角色与少量平涂色组织引导，
让黑墨轮廓与稳定无衬线承接内容；在这个种子中，角色插画以叙事组织引导。
这不是所有装饰插图的通用要求；其他表达可由温度、节奏和个性成立，仍看整体相容性。
进入填写／比较后减少装饰密度，功能图标保持熟悉与对齐。不要把边框全画歪或用
手写字体承担长文。若角色妨碍扫读、引导比工作更长，收缩叙事区域。

Claude 当前客户端、DeepSeek Harness 与 AgentParty 暂作有边界的案例：前者缺正常
会话／输入完整证据，DeepSeek 当前源码变化未完成复核，AgentParty 缺原产品运行
画面。可借已证实的局部关系，不能当完整设计规范。暖编辑旧试作可作一般阅读气质
对照，不能再代表 Claude。依据边界明确时，不为齐全把所有案例升级成种子。

## 怎样检验指引已经有用

在真实内容里看主体、辅助和行动是否一眼能分辨，实际完成切换、输入、返回与反馈；
再检查整页、局部、窄屏和当前任务有的长内容／空态／失败态。短摘要孤尾、图标光学
错位与次要区域缺设计都不能靠“没有溢出”排除。错误反馈属于原动作，成功结果属于
原对象；克制的空态也要说明为什么空、下一步是什么。

迁移验证选择未参与调参的新对象，让执行者只接收任务、skill 和所需参考，先留下
设计决定及其依据，再看产物。评审分开检查任务满足、形神关系、视觉质量与偏好；
原型合理不认证品牌还原，用户喜欢也不能抵消操作丢失。新业务仍需自行设计具体流程；
执行者无法由指引确定主体、辅助、动作与跨尺寸关系，或只能照搬旧样板，才说明迁移
指导不足。若是手艺漏项则修局部执行，不不断膨胀方法。
