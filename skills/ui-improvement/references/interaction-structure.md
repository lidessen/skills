# 交互结构：任务怎样经过空间与控件

用于识别或改进选型、页面组织、步骤、上下文与返回问题。风格种子约束表达，不能
替代控件的任务语义。先走一个完整活动，再判断卡点发生在哪个关系上；不以统一
radio、dialog 或更少点击为目标。

## 从动线定位症状，提出替代方案

观察进入 → 识别对象 → 获得必要信息 → 比较／决定 → 行动 → 结果 → 继续或返回。
无需为局部任务画完整流程图；把当前要做的动作和它依赖的上下文连起来即可。
看到重复跳转、隐藏选项、正文与输入来回滚动、改变选择却失去草稿、结果离开对象，
先指出用户被迫额外做什么，再比较现有结构与最小替代。

不能只报告“应该换 radio”或“应该用 dialog”。说明需要显露的差别、要保住的上下文、
选择时机与取消／返回，以及替代的代价；选择与宿主合同相符的表达，实际完成同一
活动复验。信息不足时核查选项规模、是否需搜索、是否必须同屏参考、是否独立长任务，
不拿缺事实当审美自由。局部方案不得改变合法选项或凭空新增产品能力。

## 选择控件按语义与比较负担决定

| 要完成什么                                   | 可用起点                               | 反转条件或易借错之处                                                 |
| -------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| 在固定互斥值中作单选，需要看见差别与说明     | radio group，选项与必要描述同时可见    | 选项很多／动态或需搜索时，展开全列表可能更难用                       |
| 在较大值域定位一个值，空间有限且不需并排比较 | 原生 select；需搜索时用合适 combobox   | 少量重要选项藏进弹出列表会增加查看与记忆负担；不是有三项就必禁select |
| 筛选同一内容或切换视图                       | 明确当前值的筛选控件；内容视图可用tabs | 改数据字段不冒充导航，不能只为有选中皮肤就声明tab语义                |
| 选择多个独立项                               | checkbox组                             | 互斥项不使用多个checkbox或多个独立switch                             |
| 开关一个立即生效的独立状态                   | switch或checkbox，标明生效时机         | 需提交的复杂配置不让switch暗示已经保存                               |
| 选择带对象属性和状态的实体                   | 可辨对象的选项列表或radio式选项        | 不能把不可用状态藏在dropdown里，也不能只显示标题丢掉比较信息         |

选择之后是否立即生效、只是编辑草稿、还是要最终提交，必须清楚；选中和焦点分别
可辨。字段标签、组名和描述有正确归属，使用已有组件或原生语义；样式不能覆盖
键盘选择、阅读顺序或不可用原因。

## 页面、局部展开、面板与 dialog

先问用户是否需要离开当前对象、是否要持续看底层材料、任务是否独立且长。

- **就地编辑／展开**：与当前对象紧密、短而常用，完成后继续原工作；注意展开后
  归属、空间与焦点，不把普通帮助内容做强制modal。
- **非模态面板**：需要同时参考或持续调整底层对象。对象切换时核对面板与草稿
  身份，不把旁边可见却无法操作的画面假装成持续对照。
- **dialog**：短、边界明确的临时子任务，结束后回到原对象；确需暂停底层操作时
  才用模态。它省去重定位但带来中断、遮挡、键盘和取消成本。
- **独立页面**：较长／多步骤／可独立定位或分享的任务，需足够阅读空间。保留进入
  来源和返回语义，不让一个小字段修改丢掉整个比较现场。

小任务也可能因移动空间使用全屏dialog，外形全屏不等于独立导航页面；是否保住
任务身份、来源、草稿、取消与返回才是关键。不要把全部设置塞进modal，或层层弹窗
让人失去主任务。确认不等于操作完成，成功反馈仍取自真实结果。

采用模态时实际核对打开焦点、内部键盘范围、取消、关闭及合理的返回焦点；取消
不应悄悄提交。采用页面／面板时实际核对返回、切对象、长内容与草稿连续性。只看
截图不能证明这些关系，按当前改动触发的路径验证，不要求不相关全产品流程。

## 动作结束后的结果归属

沿真实动作看结果落在哪里，而不只核对提示文案。一个对象中有多个编辑活动时，
分别辨认本次改变的字段、仍未提交的草稿、反馈的视觉邻接及关闭后的焦点。
文案写对对象名称，不证明用户能分清哪次操作已完成；回执放在另一操作下方，
仍可能暗示那份草稿也已保存。优先把结果放回改变的事实或动作附近，采用现有
状态与组件表达，不为视觉归属新增通用投递或反馈协议。复验保留另一活动的草稿，
实际完成、取消并返回，确认结果位置和未保存含义同时成立。

把一次变化的所有表达作为一组复看：字段、预览、状态文字、按钮图形和下一动作。
取消后字段恢复而预览不恢复，或暂停动作的标签已变而图形仍表示播放，都是组内
关系未接好；静态对齐与单项断言发现不了。反馈文字也要在当前前景里实际读，模态
背板下的提示不能只凭DOM可见就验收。不要求每次穷举全产品，沿本次改变的事实与动作核对。

## 依据与边界

2026-10-04 读取现行正文：[W3C radio](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)
说明互斥单选及键盘／组标签；[combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
区分select-only、可编辑及建议选择；[modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
说明模态、焦点、关闭与返回。这些支撑实现语义，不决定每个产品的最佳载体。
[GOV.UK radios](https://design-system.service.gov.uk/components/radios/)与
[select](https://design-system.service.gov.uk/components/select/)提供选择可见性和选项规模
的实践指导；[NN/G modal 与 nonmodal](https://www.nngroup.com/articles/modal-nonmodal-dialog/)
解释中断与底层材料参考的代价。它们不是本 skill 的性能实验，不给固定选项数量或
点击数作为统一阈值。上面的载体比较是据此形成的迁移方法，仍须当前任务实看实用。
