# 具体配方：阴影、配色、边框与动效

2026-10-04 核对来源。关系依据来自公开设计系统；下面的 HEX、CSS 和时间是可试作
起点，不是品牌官方 token，也不是本产品默认主题。项目已有主题与组件时，先映射到
其语义角色，不直接散落硬编码。可打开 [交互样片](../assets/surface-recipes.html) 比较。
样片只表达材料组合，不代替真实页面的构图、业务状态或浏览器行为验收。

## 阴影：接触层与扩散层一起配

来源：[Geist Materials](https://vercel.com/geist/materials)、
[Atlassian Elevation](https://atlassian.design/foundations/elevation/)。它们按层次配合
表面与阴影；暗色还靠表面明度区分层级。下列双层 CSS 是试作配方。

| 角色     | 可试作组合                                                 | 判断与反例                                                          |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| 平面内容 | 无阴影 + 1px柔和边框，或同组共用分隔线                     | 留在页面中；不把每一行都做成悬浮块                                  |
| 轻抬起   | `0 1px 2px rgb(0 0 0 / .06), 0 6px 16px rgb(0 0 0 / .05)`  | 第一层贴住边缘，第二层扩散；配白色/较亮表面，适合少量需要抬起的对象 |
| 浮层     | `0 2px 6px rgb(0 0 0 / .08), 0 20px 48px rgb(0 0 0 / .14)` | 配明确轮廓和独立表面；普通列表用它会变重                            |
| 暗色浮层 | 较亮的表面 + 柔和亮边 + 深阴影                             | 不只把浅色阴影加黑；注意背景、内容面、浮层的明度顺序                |

模态遮罩表达背景暂不可交互，阴影表达空间层次，两者不是同一机制。不要用内阴影
让普通文字面像输入框；确实要表达凹槽时，另核对其用途。卡片不是必须在 hover 时
上浮：只有可操作对象才考虑回应，静态内容抬起可能制造错误暗示。

## 配色：先把角色配齐，再选择色相

来源：[Geist Colors](https://vercel.com/geist/colors)区分背景、交互背景、边框、主次
文字等角色。下面是原创试作色组，不是该系统数值；局部颜色不能证明整体风格成立。

| 角色          | 冷静中性  | 温和纸面  | 暗色工具面 |
| ------------- | --------- | --------- | ---------- |
| 背景          | `#f6f7f9` | `#f6f3ed` | `#14161a`  |
| 内容面        | `#ffffff` | `#fffdf8` | `#1e2127`  |
| 次级面        | `#eef1f5` | `#eee8dd` | `#282d35`  |
| 细边框        | `#dce1e8` | `#ded6c8` | `#424955`  |
| 主文字        | `#202630` | `#302c27` | `#eef1f5`  |
| 次文字        | `#596574` | `#6b6256` | `#adb7c5`  |
| 强调文字/填充 | `#2458b5` | `#496346` | `#a8c7ff`  |
| 强调浅底      | `#e8effb` | `#e7eee1` | `#243650`  |

配法：大面积保持中性，色相集中在当前选中、相关链接或主动作，语义错误/警告另保留。
强调浅底配同色系较深文字，实色按钮配足够反差的文字；暗色强调填充通常需深色字，
不能照抄浅色的白字。灰边框只作轻分组；控件若靠边框辨认，应增强到实际可辨强度。
这些颜色可混成难看的组合：不把暖灰背景、冷灰面、不同饱和度的蓝随意拼在一起。
选定一套后调整相关角色；最终在实际相邻背景上核对文字、控件与焦点反差。

## 边框：实线、虚线与强调环各有语气

| 手法       | 起点                                                    | 用途与反例                                                             |
| ---------- | ------------------------------------------------------- | ---------------------------------------------------------------------- |
| 安静实线   | `1px solid var(--border)`，无阴影                       | 稳定对象或分组；避免外卡、内卡、字段卡层层重复                         |
| 虚线空位   | `1px dashed var(--border)` + 中性浅底 + 明确动作        | 可试用于“添加到这里”的区域；必须真有添加动作，不能给已完成内容随机虚线 |
| 拖入反馈   | 拖入时增强边色/底色，并给出可接收状态                   | 上传确实支持拖放才使用；不能只画一个假拖放框                           |
| 重点侧线   | 一侧2–3px强调色 + 同色系浅底                            | 注记或当前项的局部配方；不能仅靠侧线表达错误或选中                     |
| 键盘焦点环 | `outline: 2px solid var(--accent); outline-offset: 3px` | 与 hover、选中分别设计；不是给全部静态卡片常驻亮环                     |

虚线空位与侧线是研究试作建议，未找到能支持它们为普适规范的证据。
[Carbon File uploader](https://www.carbondesignsystem.com/building-blocks/core/components/file-uploader/guidelines)
提供拖放区域的行为语境，不用于宣称本配方数值或虚线是其规范。
浏览器原生 dashed 的段长由实现决定；需要特定虚线节奏时才另做 SVG/背景实现，
并核对圆角和缩放，不为装饰新增复杂组件。

## 圆角：轮廓配套，不是全部胶囊化

可试起点：字段6–8px、内容面12px、浮层16px；它们是样片尺度，不是全局标准。
内外嵌套时参考留白协调轮廓；内容面内边距很大却给小字段巨大圆角会像不同语言。
胶囊适合短标签或某些短动作，长输入、列表和大面板未必适合。
先复用项目现有轮廓族，必要时改变角色关系，而不是仅靠把圆角加大“变精致”。

## 动效：属性、距离、时间与曲线一起配

来源：[Atlassian Motion](https://atlassian.design/foundations/motion)按交互与过渡
区分时间，并按进入、退出、重排选择曲线；当前体系部分处于 Early Access。
下列配方是可调整的示例，非要求全部采用。

| 场景          | 具体配法                                                        | 反例                                                           |
| ------------- | --------------------------------------------------------------- | -------------------------------------------------------------- |
| hover/press   | 背景/边色120ms；按下可用100ms轻微缩放至`.99`                    | 仅可交互对象；不让每条静态内容都移动                           |
| 菜单/浮层进入 | opacity 0→1、translateY 6px→0，180ms `cubic-bezier(.2,.8,.2,1)` | 同一次出现只有一个主要运动，不让每个子项各飞一次               |
| 退出          | 淡出120ms，可减少位移                                           | 不为播完动画阻塞下一动作，快速重开不能闪回旧内容               |
| disclosure    | 箭头旋转90°，140ms；内容必要时做短距离淡入                      | 不用固定巨大max-height伪造任意高度；展开期间滚动和焦点仍应正确 |
| 保存反馈      | 成功后在原操作附近出现简短反馈，可180ms淡入                     | 不预播成功；不能用短暂动画作为唯一回执或把整页弹跳             |

优先明列 transition 属性，例如 `background-color 120ms, border-color 120ms`，
不使用 `transition: all` 让宽度、位置与主题切换意外一起动。opacity 与 transform
适合局部试作，但性能仍取决于真实规模。滚动、取消、连续点击和主题切换要实际看，
截图只能证明某一帧。[减少动态偏好](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
下关闭非必要位移与缩放，保留状态信息；不要全局抹掉项目已有必要反馈机制。

## 成组使用的起点

- **平面工具**：中性底 + 实线分组 + 少量色相强调 + 快速颜色反馈；保留内容密度。
- **温和纸面**：暖中性底 + 轻抬起阴影 + 柔和轮廓 + 克制动作；不把每个小块都做成纸卡。
- **暗色浮层**：较亮表面 + 亮边辅助 + 双层深阴影 + 短距离进入；层次由表面一起完成。
- **等待添加**：局部虚线空位 + 明确下一动作 + hover边色回应；如果只是一个普通按钮，
  不必扩大成大面积占位框。

这些是材料配方。先核对要表达的角色，再与 [视觉修辞](visual-rhetoric.md) 的组织手法
组合，带回真实页面复看；好看的独立卡片不证明整个页面已经有气质。

## 样片验证范围

本机普通 Web 预览，Chrome 实看1440与390宽度；三套配色、添加回应、反馈显示/清除、
disclosure及减少动态偏好通过，无横向溢出。主题改变会触发按钮短颜色过渡，截图在
有关动画完成后取稳定画面，不把中间灰色帧当最终配色。格式和本地引用检查通过。
