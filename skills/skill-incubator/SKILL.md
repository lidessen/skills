# Skill Incubator · 技能孵化

把真实困难发展为 Agent 可重复使用的方法。核心是复用已成立的关系，针对当前未知设计
认识活动，形成能解释取舍的方法论，再落实为可执行、可反馈、可续接的工作流。
理论提供候选和解释，实践可以推翻它；生成文件不是效果证明，试验也不只是迎合偏好的剪枝。

## 恢复起点与现有方法

确定目标任务、反复出现的困难、接收 Agent 的环境及本轮交付：研究设计、候选制作、
实验验证或正式接入。先看已有方法、可靠案例、用户已接受的方向和当前证据；只重做
不足或被反例击穿的部分。未知先标清，不从“再加一个 skill”反推必需性。
从最相关的已有方法与证据开始，只有缺口会改变当前选择时才扩大读取，不默认搜遍技能库或历史。

参考技能按任务匹配并标证据：结构良好是设计参照，已有行为观察是有限实践参照，
有匹配改善才支持增益判断；知名、长文和自评不能使它成为已证明优秀的对照。
简单且方法明确的任务直接实施或包装，无需启动完整孵化。

## 设计核心，再组织工作流

用一条具体关系解释：困难在哪里，改变哪种判断或行动为何可能改善，依赖什么条件，
什么反例会迫使改判。比较沿用已有方法、修正接合与引入新方法的实际代价。
人格可调整注意和收束倾向，不能替代知识、手艺、工具或工作组织。

将核心落实为对象与输入、默认行动、关键依赖、反馈与转向、完成与返回。
执行者应知道从哪里开始、怎样选择下一步、什么时候不能推广或宣称通过，而不是
自行重新发明流程。完成条件服从用户任务；权限和硬保证仍由宿主与工具承担。

默认工作关系如下，已有产物从对应位置接续，反证只重开受影响决定：

| 工作       | 要形成什么                         | 怎样进入下一步                       |
| ---------- | ---------------------------------- | ------------------------------------ |
| 恢复起点   | 问题、基线、有效承诺和下一关键未知 | 现有方法足够则复用，否则设计候选     |
| 设计核心   | 作用解释、前提、取舍与反例         | 选择能补足当前认识的活动             |
| 组织执行   | 默认路径、条件分支、资料能力与交接 | 写成可独立执行的候选 skill 或任务块  |
| 评估与试作 | 设计缺口、实际行动、产物与失败解释 | 以有区分力的证据决定保留或修订       |
| 修订沉淀   | 可迁移关系、证据限制与下一入口     | 交付本轮成果，需要时用新对象继续验证 |

缺事实就观察，缺解释就调研，缺解法就制作，缺偏好边界就对照，缺因果依据就实验，
缺组合或规模依据就迁移试验。活动可融合：试作改变诊断，调研生成新候选，反馈修正
评价条件；不能只筛选现有方案，也不把所有活动变成每次必经阶段。

## 以最便宜的充分证据推进

先核对设计、资源与适用情境（L0）；需要知道执行者能否作出关键判断时用短探针（L1）；
仍有影响采纳的产物、手艺或组合未知时，再开展隔离的完整试验（L2）。必要的效果问题
不能因预算低就降成静态通过；受阻时交付有效成果与明确缺口。
L1 检查局部决定或动作，L2 完成一段有实际产物的领域工作；静态设计试作也可以是 L2，
但只能支持静态表达结论，不能因为实验完整就宣称交互或运行效果已验证。

实验前固定当前问题、任务条件、比较基线及接受依据。探索可生成新候选；比较要保持
影响归因的条件一致。早期用真实对象的隔离副本或有依据的场景，保留内容与状态复杂度；
不靠正式工作的生产修改来试错。实施与模型调用仍限于本轮授权。
比较至少交代任务材料、执行工具、资源预算和评价条件；无法匹配时报告差异与观察，
不把结果差异单独归因于 skill。
把已确认的预览、编辑边界和检查入口随试验任务交接，基线与候选获得相同环境信息；
入口须在接收者环境可达，主 Agent 可用不等于子 Agent 可用；不同宿主的标识也不能照搬。
不要只说“工具可用”而让执行者重复猜测。遇到资源冲突先调整调度，能力缺口与方法失效
分别处理；等待与有效执行分别记录并保留总成本，不把资源争用单独归因于候选方法。

检验自主诊断时，让独立执行者接收候选、任务和原始材料，不提供预期答案；无委派
条件时可自行推演或试作，但说明自评限制。反例、失败和无收益结果都进入解释。
用未参与调参的对象核对迁移，不把同一正文的改写当跨任务独立样本。

## 分开修订候选与孵化器

先分清：没有发现或使用方法、方法错误、表达误导、执行能力缺失、评价器失真。
修对应关系，不能每次追加例外，也不能将“按流程执行”当作产物正确。

领域候选失效先修领域方法；只有选错活动、实验无区分力、交接失真或提炼错误时，
才修孵化方法。记录各自版本与理由；两层同时变化就报告混合影响，不声称独立归因。
评估标准在比较期间保持稳定，需改时重评基线或说明不可比较。

量化评价以具体关系和风险定位为主，分数不等于性能概率；校准评估器后再用它改孵化器。
新分数更高不足以证明更好，还须保留必要行为、成本和有差异的对象。
基线已达目标、候选无明确收益时，保留基线并定位仍有区分力的未知；可以收缩候选、
加强已有方法或停止新增载体，不用继续加正文制造进展。小型样板的执行证据不能代替
规模压力下的扫描与组织收益。

## 沉淀与交付

把触发、理由、转向与边界留在方法，把任务参数、研究历史与实验记录放回其负责位置。
提炼可能是更新已有 skill、增加按需参考、独立新 skill，也可能保留普通任务表达。
不把理论、实验协议和评分表全塞进产出的领域 skill，不创建永久总控或默认定时运行。

交付候选或实际改动，说明核心、工作流、复用与新增关系、支持证据、已知边界和下一未知。
只要求写 skill 时，文件与设计核对完成即可交付；要求实践则继续授权试验；要求证明稳定
则核对重复产出和跨任务证据，不把任一完成范围升级为另一范围。

## 按需深化与相邻边界

- 需要发展候选、设计实验、执行交接或分析失败：读 [方法发展](references/development.md)。
- 需要八维量表、低成本探针、对照和评估器校准：读 [质量评估](references/quality-assessment.md)。
- 需要批量繁殖方法、A/B重组、条件表达及Agent小轮/用户大轮选育：读 [遗传演进](references/evolution.md)。
- 需要理解审美试错与扫描工作量的接合：方法发展参考内有 UI 推演；它不是已验证 UI skill。

载体成立性、拆合、表达与激活归 [agent-guidance](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/SKILL.md)；整体责任
与体系接线归 [architecture](https://github.com/lidessen/skills/blob/main/skills/architecture/SKILL.md)。外部吸收按需用
[research-synthesis](https://github.com/lidessen/skills/blob/main/skills/research-synthesis/SKILL.md)，核心被补丁带偏时用
[design-forge](https://github.com/lidessen/skills/blob/main/skills/design-forge/SKILL.md)。本方法承担候选的发展与证据反馈，不替代这些
局部判断或领域执行。带入现有成果，只转交未决问题；缺少相邻 skill 也可独立交付本轮结果。
