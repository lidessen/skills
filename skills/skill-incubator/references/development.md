# 从理论与实践孵化方法

孵化要找出一种可迁移的工作关系：它改善哪个反复出现的困难，为什么可能有效，什么条件下
会失效。理论提供解释与候选，实践修正解释；最终 skill 保存可用的判断，不保存完整研究过程。
孵化本身复用稳定的方法论和工作流，针对具体未知选择活动；已有成果直接接续，不从空白
重建，也不为小修订重新执行全部工作。

## 把核心选择发展为工作关系

默认工作流以 [主入口](../SKILL.md) 为准；本参考深化活动选择、交接、实验与失败解释。
比较候选及孵化器改进时按需复用 [质量评估](quality-assessment.md)，不重复维护一套阶段表。

核心方法回答“为什么这样组织工作”，工作流回答“现在怎样行动”；二者都要设计。
例如 UI 方法的核心可以是以真实内容的整体关系指导局部试作，再沿消费者差异传播；
工作流则需要明确如何扫描形成对象、选择试作点、反馈改变诊断，以及传播后怎样复看。
只列调研、试作、评估等活动名，仍未形成方法；只写价值立场，也不足以交给 Agent 执行。

先检查现有 skill、可靠实践、用户已接受的取舍与过往实验。保留已成立的核心与接线，只
重做证据不足或被反例击穿的部分；名称相似不足以证明可复用，必要时核对适用条件。
活动选择使用下节策略，表达复用 [composition.md](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/references/composition.md)，证据复用
[evaluation.md](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/references/evaluation.md)。复用的是判断与工作关系，不要求每次加载全部参考资料。

## 将方法设计成 Agent 能执行的工作

沿实际执行路径检查：能否发现入口、拿到对象、作出下一步判断、完成允许的动作、核对
结果并交还。可靠性来自清楚的关系与可观察执行，不靠角色形容词或要求自报“已理解”。

- **入口与默认行动**：说明触发、所需材料和第一步怎样选；初次执行无需自行发明整套流程。
- **工作单位与覆盖**：说明处理的是页面、状态、组件用法还是其他对象；共享结果如何复用，
  哪些差异需要另看，避免代表对象悄悄替代全部范围。
- **判断与转向**：把“继续打磨”写成可辨认的条件；无有效候选时回到生成，诊断被推翻时
  回到观察，不能判断时保留未知或交接，不规定固定纠错次数。
- **完成与返回**：写明产物、证据、缺口及接收者；长任务在已有记录中保留当前对象、有效
  结论和下一步，让后续 Agent 能继续，不要求恢复先前模型或工具现场。

权限、数据一致性及不可绕过的限制由工具与 runtime 保证；skill 描述如何使用这些能力，
不通过增加指令声称获得硬保证。工具能力不足时修环境或缩小可证明结论，不能靠更严门禁
或更强人格掩盖缺口。具体表达不必逐项列标题，但会改变行动的关系必须可找到。

试验中分开检查“方法没有被执行”和“方法被执行却无效”：前者核对入口、材料、歧义与
执行环境，后者重查核心与适用条件；两种原因也可能同时存在。执行完全符合流程，仍不
代表产物质量成立。孵化过程自己也沿这条工作流运行，并据自身偏差修订，而非每次临时设计。

## 选择能产生当前所缺认识的活动

先判断下一步需要发现事实、生成解法、明确偏好，还是检验解释。候选空间尚未形成时，
不能只做比较剪枝；用户喜欢某个结果，也不能据此证明方法可迁移。按当前未知组合活动：

| 当前缺什么                   | 优先活动                           | 怎样改变下一步                         |
| ---------------------------- | ---------------------------------- | -------------------------------------- |
| 不知道现场问题与工作怎样发生 | 观察真实对象、操作和工作过程       | 修正问题定义，区分症状与原因           |
| 不知道已有解释和解法         | 调研作品、理论与实践，核对成立条件 | 生成或改造候选，也可能撤回当前假设     |
| 没有能比较的有效方案         | 制作、探索和局部试作               | 生成新表达，暴露原先没想到的约束       |
| 用户偏好或价值取舍不清       | 有具体差异的对照与反馈             | 明确适用的偏好边界，不把偏好当普遍质量 |
| 不知道哪个关系产生效果       | 区分候选的实验、反例或消融         | 支持、收缩或推翻解释                   |
| 局部有效，规模与组合未知     | 扩大覆盖、迁移和组合试验           | 判断传播条件、工作成本与回归           |

这些活动不是互斥阶段。试作可以推翻问题诊断，调研可以改变实验材料，用户反馈可以揭示
遗漏的活动。只把会改变下一步的结果接合起来，不把所有策略逐一执行。理论提供的解法
不足时回到制作，反复制作仍不能解释失败时回到观察或调研；不要只增加候选数量。

## 从工作压力提出候选

先说明当前普通做法哪里不够：不会判断、过早收束、遗漏范围、实现困难，还是资源不足。
沿用真实任务与已有方法作为起点；尚未实际观察的困难标为假设。不要把“需要更好的 Agent”
直接翻译成更强的人格，也不要把工作量大翻译成更长的检查清单。

按困难选择有用的理论或实践来源。外部材料的语境、证据和迁移取舍可按
[research-synthesis](https://github.com/lidessen/skills/blob/main/skills/research-synthesis/SKILL.md) 核对；已有可靠研究直接复用。
理论、作者经验、用户偏好与本地观察分别保留来源，不能互相替代。

把启发写成能被案例推翻的关系：在什么情境下，改变哪种注意、比较或行动，预期产生什么
差别，什么结果意味着解释不成立。例如“先看整屏节奏，再修局部间距”比“成为审美大师”
更可检验。理论不能解释的手艺判断仍可通过试作学习，不要求为每个参数寻找理论背书。

人格材料是可选的工作偏好，不是能力保证。若困难是探索过早结束，可以试验保持候选开放
的倾向；若是反复发散而不落地，可以试验及时收束的倾向。具体设计按
[agent-personality](https://github.com/lidessen/skills/blob/main/skills/agent-personality/SKILL.md)；不按类型名预设谁擅长审美或扫描。
同一 Agent 可以在不同情境中转向，也不必为每种倾向设置一个永久角色。

## 在隔离试作中发展候选

把候选写成短任务表达或独立指令块，选能触及当前困难的对象试用。早期优先使用真实对象的
隔离副本或有依据的实验场景，保留真实内容、状态与工作复杂度；正式交付留给成熟候选的
迁移检验，不靠修改生产环境来试错。已知方法可以直接写入 skill 后在使用中修订；
不确定关系宜先试作，不为等待完美证据阻止探索。
实验草稿、研究记录与已接受方法保持可辨认，不用新状态机管理孵化。

先确保任务、事实、工具和执行条件足以开展工作。无法观察实际页面、缺少必要数据或工具
能力时，指出环境缺口，不能归咎于人格或靠追加 prompt 补出能力。实践授权沿用任务范围；
设计孵化方法不自动授权执行产品任务、调用外部模型、发布或建立定时工作。
试验交接带入已确认的执行入口及边界，让双方使用同等环境信息。执行者发现工具缺口时，
先核对任务提供的替代能力；既有可用入口没有交清楚是试验准备问题，不是候选方法失败。
以接收者的实际工具与权限为准，不从主 Agent 的可用能力推断子 Agent 能力。并行试验若
争用同一浏览器、视口或写入资源，先隔离或调度；记录等待与有效执行，避免混入方法成本。

探索中可以变更候选，但要保留原对象、做了什么、看到什么、为何转向。比较依赖原始
版本且副本会被执行者改写时，先保留所需基线再启动；启动后的复制或哈希不能补作
启动前证据。漏留基线就说明能依赖的原始截图、材料或恢复来源，不伪称版本冻结完整。
这只是比较所需的准备，不要求每次工作创建额外快照系统。
要判断某条指导的贡献时，比较条件尽量一致；同时增加预算、换模型、改工具和加角色得到的改善，不能单独
归因于 skill。具体证据强度沿用 [evaluation.md](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/references/evaluation.md)，不另建评估系统。

探索实验允许生成和重写候选；比较实验才围绕已明确的差别控制变量。预期哪种观察会使
下一步不同，应在实验前说清；两种结果都会导致继续原方案时，实验可能没有区分力。
真实任务压力的场景与专门放大某个矛盾的场景可以互补，分别说明它们支持的结论。

观察偏差后先分清原因：任务不适合、理论解释不成立、表达误导、方法没有被使用，或执行
条件不足。修正对应关系；不要给每次失败追加一个例外，也不要把成功案例的全部动作固化。

## 分开修订领域方法与孵化方法

让执行 Agent 接收候选方法、共同任务和原始材料；检验自主诊断时不提前提供预期答案。
主 Agent 核对实际产物与证据，用户裁决涉及其偏好的取舍。审美接受、合同正确、覆盖完整
与成本可承受分别判断：漂亮但丢失关键操作的方案不能靠偏好得分胜出。

检验自主发现能力时，普通任务与执行者可见材料中不泄露缺陷类型、位置或修法；评价方
单独保存依据，并核对疑点是否在真实对象上成立。分别记录发现、修复和回归，保留漏检、
误判与清单外有效发现。只比较整体偏好会掩盖具体缺陷，只有已知缺陷命中又可能鼓励
机械纠正合法差异；据本次能力目标同时观察这两种代价。专门构造的缺陷只能支持相应
发现情境，不能当成正式产品或所有未知问题的覆盖证明。

评价方带有位置或偏好提示时，先把它保存为待核对的假设，不能凭提示确认缺陷。
观察执行者是否自主提出具体关系，再比较试作前后；另一个评审未认同也保留为分歧。
要判断方法是否只记住案例，可换内容、角色或空间位置检验迁移；尚未做迁移时不报告
稳定能力。领域 skill 提炼观察关系，不写入这次问题的坐标或必改结论。

先据结果修订领域 skill，再问孵化过程是否遗漏了会改变取舍的信息。领域方法失效可能
只是候选尚不成熟，不必每次都改孵化方法；只有问题来自选错活动、实验无区分力、交接
失真或错误提炼时才修对应关系。记录两层分别改了什么、为什么，避免同时变更后无法解释。
若两层确需一起改，报告混合变化，不声称独立归因。

用新对象检验修订，而非只重做已经用于调参的场景。孵化方法是否改善，还要看它在另一
候选或困难上是否作出了更有效的活动选择；把本次教训写进文档只证明已修订。

## 将经验提炼为可重复判断

从有用的试作中提取触发、行动理由、转向条件与边界，而不是复制工具顺序。例如保留
“共享样式变化后重看受影响用法”，不保留“总是打开五个页面”；保留“无法区分候选时换
真实内容比较”，不保留“每轮必须做三个方案”。

用另一个有差异的对象检查迁移：哪些关系能复用，哪些只是当前项目或用户的偏好；再用
相近但不应触发的任务检查边界。按会改变采纳判断的未知补验证，不要求固定轮数或全部
理论都被证明。没有匹配比较时可采纳有依据的候选，但只能报告观察与未知。

再按 [formation.md](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/references/formation.md) 决定载体。结果可能是更新现有 skill、加入按需 reference、
保留一次任务指令，也可能是确有独立触发的新 skill。仅把已有技能串成调用清单不构成新方法。
普通入口保留稳定方法，形成历史和失败材料留在现有研究位置，不作为每次执行的阅读负担。

## 案例：持续改进 UI

以下是孵化推演，尚不是效果已验证的 UI 方法。用户的压力同时包含审美试错与扫描工作量，
两者相关但完成依据不同：扫描充分不证明美感改善，漂亮的样板也不证明范围已覆盖。

| 困难                         | 候选工作关系                                                             | 实践要观察什么                               |
| ---------------------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| 看出不协调，却只会改零碎参数 | 从真实内容的整屏关系提出诊断，围绕诊断试作，再复看完整动作               | 阅读层级、比例与动作是否改善，还是只换了外观 |
| 一个页面漂亮，其他用法遗漏   | 按用户入口、组件用法与状态展开覆盖，区分共同根因和消费者差异             | 遗漏是否减少，共享修改是否破坏其他状态       |
| 为全面覆盖而没有精力打磨     | 广度扫描发现对象和共性，深度试作解决关键未知，再把有效关系回到受影响用法 | 深挖的收益是否迁移，剩余对象是否仍有明确处置 |
| 每轮继续改，却越来越漂移     | 保留已接受方向与基线；新观察有实质收益才改，反证足够时重开方向           | 是否保住既有改善，是否因追求变化而制造退步   |

先在一个包含真实内容和关键状态的页面或组件用法上试作，降低探索成本；代表性对象用于
发现方法，不能冒充全量验收。探索到有效关系后再扩大覆盖；仍有未决视觉问题的对象可以
继续试作，不把“一次样板成功”变成全仓机械推广。

审美判断以任务和项目当前方向为依据，选择适合的设计方法，不指定某项设计 skill。
项目已有扫描、实现核对、任务
分治与复测方法时，分别复用其能力；没有这些 skill 也可用普通任务分解完成，不递归加载
全部相邻方法。项目方法由各项目自己的入口路由，这份通用方法不绑定项目路径。

共享根因优先修在负责位置，同时复看消费者；页面特有构图在页面中处理。扫描可并行的
部分与共享写入责任按环境安排；审美方向的分歧由总体判断综合，不按投票平均拼装。角色
有不同分工时，产物差异首先是分工证据，不能称为人格效果。

“持续”应落在有范围、有基线、能续接的改进批次：每批完成授权工作并保存关键观察、
实际覆盖、待验项及下一入口。没有实质改善时允许保留；停止当前批次不等于宣称永远完美。
用户要求全量时逐项完成或如实报告缺口；探索预算有限时报告范围，不把抽样改名为全量。
未来自动运行和通知只有用户请求时才安排，skill 文本本身不会持续运行。

可能值得沉淀的新增关系是“扫描发现压力，试作形成局部解法，传播后检查差异，再据反证
修订”，而非另起一份设计规范。若现有方法组合已能做到，就加强接合说明；只有实践发现
这份结合反复缺失且有独立选择价值，才提议单独的持续 UI 改进 skill。

## 用假想反例检查设计

以下仅是推演，用于暴露方法缺口，不代表已经观察到 Agent 行为或 UI 改善。

| 假想情境                                       | 单一策略怎样失效                 | 方法应怎样转向                                                                     |
| ---------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------- |
| 用户说“不够高级”，现有方案都缺乏重点           | 对照剪枝只能选出相对不差的方案   | 观察实际内容与动作，研究相关作品，再试作新构图；有可辨别差异后才校准偏好           |
| 用户选中了稀疏样板，长标题和错误反馈加入后崩坏 | 喜好被误当成完整质量验收         | 保留偏好方向，改变内容与状态检验表达，修布局而非否认反馈                           |
| 调研了很多理论，Agent 仍只会统一圆角和间距     | 更多书目并未转成制作判断         | 缩到具体构图试作，检查理论怎样改变选择；无作用的理论退出执行入口                   |
| 两种试作都不好，原因是信息职责划分错误         | 继续换参数不能生成有效候选       | 返回问题诊断与表达载体选择，重新组织信息后再比较                                   |
| 一个页面改善，共享 token 推广后破坏密集列表    | 将局部参数当作可迁移关系         | 检验消费者差异，区分共同语义与情境参数；必要时收缩传播范围                         |
| 一百个用法逐项打磨耗尽预算                     | 审美试错吞掉覆盖，清单又吞掉探索 | 按共同关系分组，以关键未知决定深挖对象；对不同用法仍保留覆盖，不用代表样本冒充全量 |
| 换成“开放探索型”角色后产物更好，但同时翻倍时间 | 把资源或分工收益归因于人格       | 需要归因时恢复可比条件；否则保留结果，注明原因未知                                 |
| UI skill 连续修改后样板越来越好，新页面却无效  | 两层都迎合同一实验，制造自证     | 换未用于调参的对象检验；领域修订与孵化修订分别核对，允许撤回过度特化的规则         |

这些反例支持的设计选择是：由当前认识缺口决定活动，让活动所得重写问题与候选，再以
不同对象检查可迁移关系。它们不能证明这套选择实际有效；实践应优先触及仍会改变取舍的未知。
