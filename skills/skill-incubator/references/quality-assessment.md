# Skill 的使用前评估与低成本校准

用于孵化候选、比较版本或检查评估器；普通任务不必评分。目标是用便宜的证据淘汰明显缺陷、
定位下一处改进，把昂贵实践留给关键未知。这里的量表是待校准设计，不是已验证的性能预测器。
方法发展与证据边界见[公开方法摘编](https://github.com/lidessen/skills/blob/main/theory/skill-development.md)，该摘编不包含原完整形成记录。

## 分开设计质量、决策表现和任务效果

- L0：读文件、核对依赖并作情境推演，评价使用前设计质量；不执行领域任务。
- L1：独立 Agent 接收短情境，选择下一行动、定位资料或处理局部交接；成本较低，已经是
  skill 使用，不能称为纯静态检查。
- L2：隔离环境中的真实任务或完整样板，检查实际产物、过程、回归与成本。完整静态设计
  也可属于 L2，但证据仅到静态表达，不证明交互或运行效果；L1 只处理局部决定或动作。

格式有效、结构评分、微探针成功和完整任务效果分别报告。只跑 L0 时可以判断设计缺陷和
试验优先级，不能声称已可靠执行、审美已改善或具有某个成功概率。流程符合不等于目标正确。

## 先冻结比较条件与关键关系

记录候选版本、任务类别、接收模型与宿主假设、允许能力、最近邻方法和此次未知。把任务
所需的关键决定、必要约束和适用失败情境列为评估单位；它们来自任务、合同及独立案例，
不能只从候选正文提取，否则遗漏的责任会从分母消失。

核对指标是否只证明了较容易的邻近目标。例如自主发现排版问题、生成方案与形成有效
设计是不同结果，前两项不能替代第三项。用户反馈击穿这个对应关系时，重评既有产物
并修正下一次实验；不要把原成功保留为完整成功，也不把“仍需打磨”写成泛化免责。
评价单位的粒度也要与声称的能力对应：整体任务成立不为未看的内部组成代签。
例如UI的对象/保存合同、整体组织和控件工艺分别取证；整屏缩览与无几何警报不能
代理内部留白。目标包含这一层而观察不足时补相应局部，不能把它改成不影响使用就算好。
能为改动作出完整解释，仍可能只是在合理化失败产物；核对实际形式与结果，不按术语
丰富程度评价方法增益。用户已否定的产物保留为反例，不靠重写理由恢复其成功地位。

比较无 skill、已有方法与候选时保持任务条件相近。成熟参考只在其证据支持的领域有效；
结构清楚的 skill 是设计参照，不能因知名或被收录就当作效果已证明的对照。
新旧版本与组合方法按实际成本一起比较，不靠增加预算或减少要求制造优势。

## 八维设计量表

每维评分使用 0–4 的有序档位，附正文或资源定位及一个具体判断；不数标题、禁令或例子。

| 维度       | 评估对象             | 使用前可检查的关系                                                                   |
| ---------- | -------------------- | ------------------------------------------------------------------------------------ |
| 触发与边界 | 能否选对方法         | 正触发、相近负触发、最近邻区别与退出条件                                             |
| 核心方法论 | 方法为何能改变工作   | 困难→作用关系→选择理由→适用前提；能解释取舍和反例，而非美德集合                      |
| 工作流     | 方法怎样落实         | 对象/输入、依赖、默认行动、反馈分支、完成与返回；失败时合法工作仍可继续              |
| 约束适度   | 哪些行为必须保住     | 必要约束足够明确，偏好不升级为能力合同，合法替代路径不会被无故阻断                   |
| 信息披露   | 所需指导何时可获得   | description 可发现，入口有支撑默认行动的内容，条件细节可定位，关键约束不藏在冷门分支 |
| 执行接合   | Agent 是否有条件行动 | 资料、工具、权限、状态 owner、前提与交接有明确来源；文字不冒充能力或硬保证           |
| 验证与归因 | 怎样知道做对了       | 目标与证据对应，执行偏差与方法失效可区分，产物自评不替代接受，未知不伪装通过         |
| 迁移与负担 | 方法能否重复使用     | 稳定关系与任务参数分开，已有能力可复用，成本与任务相称，续接不要求重建全部背景       |

统一档位用于表达判断强度，不是算出的客观性能：

- 0：对应的关键关系缺失、矛盾或明确误导。
- 1：提到了目标或活动，但无法恢复如何判断和行动。
- 2：普通路径能执行，仍有影响取舍的适用条件、分支或接合缺口。
- 3：此次任务类别中的关键关系完整、自洽，正常和适用失败情境可推演。
- 4：在 3 的基础上，独立于作者预设的边界或迁移案例仍能由同一关系解释，无需逐例补丁。

4 分仍可能只是静态推演；它不代表真实执行已验证。小型 skill 不因没有复杂流程而扣分，
审美方法不因允许手艺判断而扣分；只评价它承担的实际责任。没有必要责任的维度标 N/A，
材料不足标 U，不能把 U 当满分或用额外空话补齐。对 2/3 等分歧保留区间和理由。

以八维向量、最低关键维度和具体缺陷为主。若需同类候选的粗略汇总，完整评分时可使用
`S = 100 × Σ(wᵢsᵢ) / (4Σwᵢ)`，初始等权只为展示，不是研究证明的权重。事前确定适用
维度与权重，不随候选改分母；有 U 时报告区间或不汇总。N/A 比例不同的 skill 不直接排名。
这是有序档位的约定性汇总，80 分不等于 80% 成功率，也不设通用的自动采纳阈值。

权限越界、错误方法、无法满足的能力前提、虚假完成或关键依赖失效单列为具体阻断，不能
被平均分抵消；阻断哪种任务就说明哪种，不据此给整份 skill 宣判失效。

## 可量化的辅助指标

这些分母和语义需要人或独立评审确认，不是关键词 regex 可以可靠计算的指标。

| 指标           | 算法或记录方式                                                     | 限制与用途                                               |
| -------------- | ------------------------------------------------------------------ | -------------------------------------------------------- |
| 关键决定支撑率 | 有可操作指导的独立关键决定 / 任务要求的关键决定                    | 正文提到活动名不算支撑；检查方法遗漏                     |
| 约束必要性比例 | 有具体风险或合同依据的硬约束 / 硬约束总数                          | 无硬约束记 N/A；同时看必要约束覆盖，避免删光约束得高分   |
| 必要约束覆盖率 | 有明确支撑的必要约束 / 独立确认的必要约束                          | 不把新增禁令当新增必要责任                               |
| 情境路径闭合率 | 输入、允许行动和终止/转向可恢复的情境 / 适用情境                   | L0 仅证明表达闭合；不证明运行可靠性                      |
| 依赖可达率     | 在目标环境能定位并合法读取的必要资源 / 必要资源                    | 文档链接存在不等于 runtime 允许读取；声明假设            |
| 披露代价       | 各代表路径需加载的文件、字节或实际 tokenizer token，附最坏必要路径 | 不设普适短文本阈值；同时看关键指导缺失，避免压缩承重语义 |
| 已确认冲突     | 同一情境下互不相容要求的数量及受损行为                             | 数量只作定位，不奖励长文制造更多可计数项                 |

L1 再测触发 precision/recall、合法路径误阻断率、关键约束遵循率、决策正确率、资源定位
成功率和失败后正确转向率。每项给成功数/适用数，样本量与未知；小样本不写小数点精度。
要求必须同时成立的情境另报整题通过率，不用逐项平均掩盖关键失败。允许多条正确路径。

## 校验评估器，再用它改孵化器

从相同 skill 制作少量有明确差别的匿名版本，例如把按需调研改成每次全读、删除消费者
复验、把真实观察改成自评、把偏好变成必须满足的参数。缺陷必须有独立可解释的受损情境。
再作保持语义的改写、换标题、换顺序或加重复文字，检查评分是否无故改变。

评审者不知道版本来源、作者、预期优劣或缺陷标签；阅读评估任务和原始材料后给逐维证据，
再揭示差别核对。必要时交换顺序或请第二评审，只复核会改变决定的分歧。
统计缺陷检出率、无害改写误报率、配对排序准确率与换序一致率；保留原始数量，不只报
一个平均值。一致只说明可重复，不能代替判断正确；作者自评不能是唯一接受依据。

缺陷变体检验评分器能否识别预设问题，不证明静态得分预测运行效果。校准材料与留出
材料按原始任务/skill 家族分开；同一正文的多份改写不能伪装独立样本。不要把隐藏答案
塞进 skill，也不要让孵化器与评估器共同改题来追求更高分。

## 孵化器怎样形成稳定能力

复用 [skill-incubator](../SKILL.md) 的工作流：冻结问题与已有方法，生成候选，经 L0 定位
缺口，再按关键未知投入 L1/L2。只改具体错误的核心、接线或表达，不以补满评分表为目标。
每次留下注明版本的领域修订与孵化修订，评估标准在比较期间保持不变；确需改量表时
重新评旧版或明确不可比较。

以多个任务家族的留出结果检查：候选相对既有方法的胜/平/负与退步原因、关键缺陷比例、
误阻断、达到可用候选的修订成本，以及结构评分对实际失败是否有排序预测力。不能只看
平均质量，少数严重退步与跨案例波动也要报告。同一孵化器的独立重复产出用于检查稳定性。

静态评分与少量 L2 结果积累后，可以用按任务家族留出的排序相关、缺陷预测 precision/
recall 等检查代理指标。样本不足时只分析案例，不拟合复杂权重；只挑高分候选实测会产生
选择偏差，需按成本保留中低分和不确定案例的抽查。模型、宿主或任务域变化后重查适用性。
只有有数据支持时才能给条件化性能预测或减少对应实践；不能承诺有限测试证明永远可靠。

## UI 候选的低成本探针示例

短情境的正确关系提前由任务合同确定，不要求唯一动作文本：

| 情境                               | 应保住的判断                                       |
| ---------------------------------- | -------------------------------------------------- |
| 用户只要一个按钮对齐               | 不启动全产品调研、扫描或人格实验                   |
| 用户不满意现有所有方案             | 允许观察与生成新构图，不只在既有候选间剪枝         |
| 用户喜欢静态样板，错误态挤压主操作 | 保留偏好，同时重查布局与动作；不以喜欢代替合同正确 |
| 共享 token 改善卡片却破坏密集列表  | 区分共享语义与情境参数，检查消费者，不机械推广     |
| 浏览器不可用                       | 交付静态判断及缺口，不宣称实际复看通过             |
| 实验中预算不足以覆盖全部用法       | 保存实际覆盖与续接，不把抽样写成全量               |

这些探针可先作 L0 推演，交给 Agent 回答才是 L1；能作对决策也不证明能制作出好看的 UI。
审美提升仍需要实际画面、交互及用户反馈。评价 UI skill 的方法设计与评价它产出的 UI
分别进行，不能让理论名称、排版术语或评审自信程度代理美感。
