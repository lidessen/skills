# 可编辑策略示例

此页只帮助主 Agent 与用户讨论选路，不是待原样复制的默认政策。核实个人可用通道与偏好后，
由主 Agent 将商定内容写到[全局策略位置](config-log.md)。不记凭据、令牌、登录态、
完整账户资料或未经确认的订阅。已有策略要读取并保留，不覆盖。

## 硬边界

- **禁止**：[准确的 runner / provider / route、禁止原因；包括决策器与执行器的 fallback。]
- **付费 API fallback**：[默认不允许；如授权，写明条件、币种和每任务或周期预算。未设上限不等于无限。]
- **任务与环境权限**：[项目规则与本次任务权限由其 owner 控制，策略不能扩大文件、网络或付费权限。]

## 套餐候选与当前可用入口

可记录用户声明拥有并允许考虑的套餐，但明确标为“待核实”；只有当前按官方方式确认
认证和计费的 route 才标为“可调用”。套餐原生 runner、官方授权的套餐集成与按量计费
API 分开。不要把订阅当作通用 API key，也不使用非官方代理绕过产品条款。

| runner | provider / 模型准确版本 | 通道与认证状态 | 共享额度池 / 限制 | 核实日期和来源 |
| --- | --- | --- | --- | --- |
| [待协商] | [待核实] | [套餐原生 / 官方授权集成 / 付费 API；待核实] | 未知 | [待填写] |

同池不同 route 不算独立余额。额度未知既不是零也不是无限；429 先区分短期限流、并发限制
和明确耗尽，按可用重试时间决定等待或改选。

## 偏好与任务适配

- **默认 runner 与理由**：[协商后填写；说明工具、上下文、恢复、隔离、质量/延迟和用户偏好，非所有任务的硬指定。]
- **备选 runner 与触发条件**：[协商后填写；说明何种能力缺口、等待或失败才改选，以及共享额度池和付费边界。]
- **优先**：[用户偏好的 runner / provider / 模型 / 套餐；前提是满足任务能力与授权。]
- **避开**：[低优先级及例外条件。避开是偏好，不等同禁止。]
- **质量、延迟、成本**：[哪些任务要更高可靠性，哪些可由较轻量 runner 完成；可接受截止时间。]
- **工具、上下文、恢复与隔离**：[执行任务必须具备的能力与验收方式。]
- **保留余量**：[需要为交互或关键任务保留的共享池余量；不以耗尽套餐为目标。]
- **决策器**：[可用且授权的 decision API / Jev 路径及计费；不可用或只剩未准许付费路径时主 Agent 直接选。]

初始化及模型、runner、套餐、条款或任务类别变化时，刷新相关目录、官方能力与费用资料，
记录版本、runner 推理档、来源日期和不确定处。一次失败是修正证据，不永久拉黑。
