# 任务委托策略

供主 Agent 和获得同样授权的决策器阅读、按任务判断。编辑方括号中的内容，删除不用的示例行。此文件不由初始化脚本解析或强制执行；不要在这里保存密钥、令牌、登录态或完整账户资料。声明拥有套餐不证明当前 runner 已认证、可调用，也不授予项目写入或付费权限。

## 硬边界

- **禁止的通道**：[无；或填写准确的 runner、provider、route 标识及原因]。禁止意味着不选，也不作失败回退。
- **付费 API fallback**：禁止。[若经用户授权，写明许可范围和条件；订阅用尽本身不授权付费。]
- **付费预算**：未授权／未设上限。[授权后写明币种、每任务或每周期上限、由谁确认用量；未设上限不等于无限。]
- **决策器与执行器**：两者均受相同的禁止通道、付费许可和预算约束；若专用 Jev／decision 接口只能经未获授权的付费通道调用，由主 Agent 直接按本策略判断。
- **任务和环境权限**：[填写需继承的项目规则；策略文件不扩大 runner、文件或网络权限。]

## 偏好与任务适配

- **优先**：[填写已认证且官方支持的套餐入口、偏好的 runner/provider/route；仅在能力和时延足以完成任务时使用。]
- **避开**：[填写低优先级通道及触发条件。避开是偏好，可在符合硬边界且有理由时改选；不同于禁止。]
- **质量／延迟／成本取舍**：[例如关键设计和复杂调试偏质量，短而可验证的修改偏低延迟；写清验收要求与截止时间。]
- **任务类型适配**：[按编码、检索、长上下文、工具调用、多模态等，写出必须具备的能力与可接受的验证方式；不凭价格、家族名或通用榜单直接选。]
- **保留余量**：[写明需为交互任务或关键任务留出的共享池额度；不以耗尽套餐为目标。]

## 刷新与任务回执

初始化、模型或 CLI 更新、套餐／费率／条款变化、目录缺项、反复失败或任务类型变化时，核查实际可用目录、官方能力与计费资料及相关原始评测。记录查询日期、准确模型版本、runner 的推理档位和不确定处；无可比数据时不编造排名。一次失败只是修正路线的证据，不永久拉黑。

每次委托记下：任务目标与范围、所需上下文、交付物和验收标准；所选 runner／provider／model／访问通道、决策依据、共享池与预算状态、Herdr 追踪标识；最终结果、验证证据、费用或额度状态（若可核实）和未解决问题。
