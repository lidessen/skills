# Agent guidance composition

## 必要关系

写 prompt、skill 正文或交接块前，恢复会改变行动的关系：

1. **对象与目标**：处理什么，期望哪种可观察变化；哪些相邻结果不合格。
2. **来源与状态**：事实、决定、约束、指令、观察、推断、候选、未知和参考分别是什么，当前
   canonical source 在哪里。
3. **接收上下文**：Agent 已有什么、能读什么、在哪个 workspace、可用哪些工具；哪些只是推测。
4. **允许效果**：能读、改、执行、发布到哪里，何时停止、转交或请求授权；prompt 不产生权限。
5. **判断与验收**：什么关系必须成立，什么证据可观察，谁拥有最终接受权。
6. **未知与失败**：缺口、冲突、能力不足或验证失败会阻止什么，哪些局部结果仍然有效。
7. **返回关系**：结果给谁，接收者下一步需要什么结果、依据、验证、未知或决定请求。

不要求每个任务都出现七个标题；它们用于防止承重语义消失。结构服从行动依赖。

一段 prompt 或 skill 方法通常沿着以下关系组织：对象形成 → 支配关系 → 当前矛盾或决策 →
允许行动 → 验证与返回。角色词、形容词和“主动一点”不能代替这些关系；例子只能帮助识别边界，
不能代替来源和方法。

## 压缩与展开

先做删除检验：删掉一段是否改变对象、来源地位、范围、判断路径、效果、失败处理、返回或
验收？若是承重语义，保留或移动到调用时仍能发现的位置。其余重复、礼貌性前言、无信息总结
和不会改变下一步的背景才压缩。

根 skill 只保留触发、主要判断、边界和路由；条件细节放 reference。description 是选择信号，
不是完整说明书。示例展示边界或契约，不能替代规则；schema 只有在下游真的需要机械解析时才用。

表达顺序通常是对象/来源/目标 → 影响判断的条件 → 行动与验证 → 返回与接受。不要要求 Agent
复述全部上下文来证明理解；只有回显能发现高风险歧义或满足外部协议时才保留。

长任务、恢复或交接时，重新加载一个短 focus anchor（当前目标、采用的方法、边界、下一步和
返回位置），不要把整个理论、历史或所有 references 重新塞回上下文。

## 多步骤与失败

包含依赖、交接、等待、并行或验证回返时，复用已有 Plan/Task/Todo work map，说明当前 bounded
task、完成观察、证据和返回位置；不要新建第二份权威计划。一步、低风险、可逆且无依赖的动作可
直接表达。

失败时返回实际尝试、观察到的错误、受阻范围、仍有效的产物和继续所需的事实/能力/授权。
不要用“已完成”包装部分产物，也不要把所有未知升级成阻塞提问。
