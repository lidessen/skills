# Guidance formation and carrier choice

## 先判断对象

从真实任务、用户纠正、失败轨迹或可复现 baseline 恢复：哪个 Agent 在什么环境中，对什么行为
对象缺什么判断或行动；这个差距是否会跨任务重复；什么结果会证明它改变了行为。保留未知，
不要从名称、目录、笔记数量或“需要一个 skill”的请求反推准入。

## 持久 guidance 与载体准入

比较相邻形式：

- 一次性任务只需要当前任务表达；项目持续边界放局部指令；事实、设计或论证放普通文档。
- 条件分支细节放 reference；确定性变换交工具；必须跨提示、重启、并发或不可信调用成立的
  属性交 runtime/base；派生视图保留 canonical source。
- skill 只承载可选择加载、可重复、能由方法表达改变且有可观察边界的 Agent 判断或行动。

候选至少要能说清：主要判断、正触发、负触发、最近邻 owner、允许效果、返回关系和行为探针。
只有需要跨任务选择性发现的方法才进入 skill；项目常驻边界、focus anchor、一次任务表达和普通
reference 各有自己的 owner。无法区分这些关系时返回 `research` 或 `no-proposal`，不先建一个万能容器。

## 生命周期处置

先判断是否仍有真实差距，再选择 `retain`、`rewrite`、`split`、`merge`、`downgrade`、
`delete` 或 `no-proposal`。篇幅和小节数量不是拆分理由；共享术语不是合并理由。

一个 skill 只有在独立触发、上下文与失败方式不同、能够分别验证且结果仍可重组时才拆分。
如果内容只是知识、项目常驻规则、一次性计划、确定性工具变换或 runtime 保证，就把它还给
相应 owner，不创建兼容壳。

## 六面 review

分别检查成立性、对象与边界、形式与上下文、Agent 表达、行为与回归、体系关系。设计“是否
应该存在”和表达“怎样写清楚”分开判断；不要用措辞变顺掩盖载体选择错误。
