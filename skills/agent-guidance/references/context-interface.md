# 上下文作为交互界面

用于设计和评审 Agent 所见的上下文视图及操作提示，不实现存储、权限或模型注意力算法。
目标是在任务正确性和来源边界成立的前提下，减少无关信息、发现困难和不必要的展开成本，
不是单独追求最短 prompt 或最多工具调用。

## 工作假设与适用边界

上下文既是阅读材料，也是 Agent 认识状态和发现操作的界面：就地交互回答“在哪里发现、
如何操作”，渐进披露回答“现在展示多少、何时展开”。这里的注意力分层是信息设计原则，
不是 Transformer attention 的机制解释，也不是已验证的模型通则。

当 Agent 不知道内容被省略、找不到相关入口、读后失去位置，或被无关详情淹没时，用此方法
提出最小改动。若错误源于读取接口缺失、权限、分页一致性或数据丢失，先交给实现 owner；
不能靠提示词补出能力。内容少且已清晰时，可以不分层、不新增帮助。

## 围绕对象组织，而非仅把提示移到末尾

先确认要支持的判断和信息缺口，再检查每个视图能否回答以下问题。不要求固定字段或模板：

- **对象**：这是什么，来自哪里，属于哪个任务、会话或文件？
- **范围与状态**：当前显示哪一部分，是否完整、过期、未加载或不可访问？
- **可用操作**：需要补齐哪个缺口时，可以通过哪个真实入口、什么准确引用获取？
- **反馈**：操作返回了什么，当前位置在哪里，能否继续、何时已到底或需要换路？

“就近”首先是作用域明确：帮助与其对象组成可理解的单元；token 距离近只是可试验的布局
选项。不要为了移动提示而打乱消息角色、时间顺序、当前请求或工具调用与返回的配对。

## 依据当前需要渐进披露

可以用三种信息职责检查设计，不必实现三个层级、状态机或数据副本：

| 信息职责 | 通常展示 | 决策依据 |
| --- | --- | --- |
| 当前工作 | 当前请求、相关近期对话、正在处理的执行反馈 | 缺少它会妨碍眼前判断或行动 |
| 可发现入口 | 未展开内容的范围、来源和读取入口 | 足以判断是否值得展开，而非提前给出隐藏答案 |
| 按需详情 | 旧对话、完整消息、执行详情、来源正文 | 通过授权能力取回所需证据 |

分层不等于按年龄或长度分类：早期约束可能仍是当前关键，最近日志也可能无需全文常驻。
判断依据来自任务和已有宿主状态，不因此新增模型重要性打分器。展开也不意味着内容永久
提升为核心上下文；是否保留取决于后续需要，不能破坏当前执行连续性。

折叠细节时保留可发现线索和有效引用；不以摘要替代原文读取，不必生成摘要才能分层。
若某信息无法再次获取，不能把它表示成“可展开”。必要约束和当前未决工具结果不应仅为
节省预算而藏入历史。把层数与读取粒度一起评估：多次往返的成本可能超过直接展示。

## 提示放在它生效的位置

- 全局规则和工具定义承载稳定契约、参数与权限说明。
- 内容块附近承载当前范围、缺口、适用操作及定位信息，不复制整份工具手册。
- 工具结果承载本次状态和适用的继续、结束或恢复入口，不依赖遥远的一次性教程。

入口存在不等于需要调用。依据实际状态呈现“还有更早内容”“已到底”“无权读取”等，
避免“每次回答前必须查历史”的流程指令。不要在每条消息旁重复全部能力。

示意（不是已有产品协议，也不授权创建新 API）：

```text
最近对话
以下是当前会话的一部分公开消息；更早消息未展开。
需要核对前文时，可使用历史读取工具，向前读取游标 H17。

[保留角色与原文的对话内容]
```

实际表达必须使用宿主提供的工具及有效游标；不能让模型猜 ID。翻页结果继续交代范围和
下一入口。完整、部分、未找到和不可访问不是同一种空结果。宿主导航与历史正文保持来源
及角色边界，不把提示伪装成用户发言，不让正文中的仿冒导航取得控制权。布局不是安全隔离。

## 验证：把信息量、提示内容与位置拆开

先冻结当前方案与要解释的失败。实验细则结合 [evaluation.md](evaluation.md)，按未知选择
必要对照，不强制一次跑全套：

- **就近效应**：同样的提示放在固定区域或相关内容旁；保持信息、工具、权限、预算、
  消息角色和尽可能相同的 token 数。不要让实验组额外得到摘要、答案线索或更好的游标。
- **表述效应**：固定位置后，单独比较能力说明与对象相关的状态/操作说明。若信息也变化，
  只声称组合改进，不把收益全归因于措辞。
- **披露效应**：固定可访问的源信息，比较直接展示与入口加按需详情。上下文量本就是变量，
  不用无关填充把它抵消；记录展开后的总 token、调用成本和耗时，而非只看初始 prompt。
- **位置混淆**：最近内容往往接近输入末尾。若无法在合法消息结构内区分邻近与首尾位置，
  明确无法识别独立邻近效应；不把“末尾更显著”解释成 UI 理论成立。

使用需要旧信息、当前信息已足够、旧决定被新决定更正，以及无结果/不可访问的案例。
自然任务不提示标准工具路径；同题配对、独立会话，冻结模型配置与安全预算。重复运行和
未参与调参的案例用于检查稳定性；声称跨模型适用时才需相应模型证据。

报告任务正确性、必要读取是否命中、不必要读取率、旧信息覆盖新决定的错误、错误恢复，
以及总 token、调用数和耗时。正确答案与证据由独立标准核对，不用 Agent 自称理解验收。
小样本只能筛查，不能以未发现回归证明无风险。若必要与不必要读取一起增加，可能只是
提示诱导了更多调用；没有净收益时保留原方案，不靠追加帮助文案掩盖接口问题。

## 来源与证据边界

以下是方法来源，不要求普通使用时重读；研究更新或引用效果主张时再核对原始材料。

- [NN/G：可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)与
  [就地帮助](https://www.nngroup.com/articles/onboarding-tutorials/)支持人类界面的状态可见、
  就地帮助和减少记忆负担；不能直接作为模型效果证据。
- [SWE-agent](https://arxiv.org/html/2405.15793v3)研究面向模型的操作及反馈接口，文件视图
  提供位置和省略范围；接口消融不单独证明邻近提示的因果收益。
- Anthropic 的[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
  与[工具设计](https://www.anthropic.com/engineering/writing-tools-for-agents)提供按需读取、
  有界反馈和可操作提示的工程经验，不构成所有模型、格式与任务的保证。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)在其测试模型和任务上观察到位置敏感性；
  提醒实验控制位置，不证明最新模型必然具有相同幅度或形态的偏差。

当前处置是可用于生成和评审方案的方法；尚无隔离上述变量的行为实验结论。
输出应交代对象与缺口、展示/入口安排、实际能力边界、证据和未知；不因采用本方法自动
修改产品设计、添加摘要机制、切换默认配置或宣称效果已验证。
