# 多轮验证与中断接续

在用户要求充分验证、反复测试，或需要恢复未完成验证时读取。这里组织证据与下一步，
不替代项目的运行诊断、行为评价或视觉观察方法。单次命令检查无需启动多轮流程。

## 保留一份可接续的工作记录

先沿用户目标、适用项目指令与现行合同确定范围、完成依据和允许的替代做法。复用本轮已有
记录；没有记录时按项目惯例保留最小工作记录，不强制目录、模板、永久台账或执行器。
记下实际版本及未提交差异、环境、工具能力、授权和预算，后续变化写在同一记录中。

条目对应一个可核对的验证问题，可引用现有用例及相关分支。覆盖与本次风险有关的正常路径、
边界、变更、失败、并发、恢复和跨模块接合，不把所有理论窗口都变成必跑矩阵。用户要求
全量时覆盖所声明的完整范围；范围改变应保留理由，不能静默缩成抽样。

如使用勾选，勾选表示**已满足本次验证目标且有依据**，不只是命令执行过。未执行、期望
未满足、等待复测或缺少必要观察的条目保持未勾选，记录事实、证据与下一步。
确实不适用的分支单列原因；缺环境、能力、授权或预算是待测或受阻，不能改成“不适用”
并宣称全量完成。可选优化不阻止满足目标的条目完成，但应与必要缺口区分。

例如，下面只是记录方式，不是实测结果：

```md
验证目标：保存被拒时不写入，并保留用户草稿。
条件：实际代码版本、未提交差异、环境与授权见本轮记录。

- [x] 无写权限保存：第1轮观察到拒绝且无持久写入，证据见对应请求与文件检查。
- [ ] 拒绝后的草稿：第1轮草稿丢失；修复后待按原输入复测，并核对正常保存仍可用。

续接：保留原输入与差异；先核对未决保存请求，再继续草稿复测。
```

## 沿原触发条件复验

沿正常入口执行，独立核对产物与原始事实，记录实际版本、条件、结果和证据。
确定性合同可以明确通过或失败；开放行为保留文字评价，接受符合目标的合理路径。
运行完成、结果正确与用户收到交付分别核实；不以一个程序状态代替其他结论。

出现偏差时先核实触发、影响、责任与反例，区分环境问题、实现缺陷、合理取舍和改进机会。
按授权修复，保留原观察；修复及复测另记，不能用放宽权限、删除数据、换资料身份或改变
必要期望制造通过。建议不自动成为代码改动或新增门禁。

下一轮应回答仍未解决的问题，覆盖原触发条件、改动影响的消费者与关键接合，并核对正常
行为。说明哪些条件变化、旧证据哪些仍适用；没有新变化或未决风险时不机械重跑全部检查。
需要新场景检验迁移时，保留它与原场景复测的区别。

随机表现需要与本次结论相称的重复和场景变化，不能凭一次碰巧成功关闭反复出现的问题，
也不规定统一轮数或反复抽样只保留成功样本。结论限定在实际观察范围内。
代码存在或一条路径通过不代表所有端、角色和候选分支已验证。

## 中断后先查状态，再行动

中断前保存已观察结果、有效产物、当前版本、现场与原工作定位、未知回执、待复测项和
下一步；涉及浏览器、桌面或设备时保留准确资源身份与 owner。只停止或清理属于本轮且已确认
可清理的资源，保留核对和恢复所需材料，不把原始私密内容复制进长期记录。

恢复时先核对同一记录、版本、资料、授权、服务、设备和未决执行。未知提交或在途工作沿原身份
查明现状，不能先重跑制造重复副作用。已有产物不等于用户已收到，日志已保存也不等于
恢复已验证。仅重开被实际变化影响的已完成项；发现原证据不足或勾选错误时，同样重开并
保留更正原因。

必要前提缺失、预算耗尽或用户中断时，留下未完成项及原因，继续不依赖它们的工作。
“测试直到通过”不授予额外费用、外发、部署或不可逆操作权限。

收尾逐项核对声明范围、必要整体路径与证据，满足全部适用目标后才报告本轮完成；其余
报告为部分完成或受阻。交还实际环境、主要观察、修复与复测、剩余限制和记录位置。
