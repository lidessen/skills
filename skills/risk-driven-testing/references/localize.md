# 项目本地化

仅在选择 `localize [target-project]` 时使用。产物是目标项目独立维护、后续 Agent 可直接使用的
测试判断方法及必要发现路由。本模式只改指导，不改产品、测试或 CI，不运行测试、安装依赖、
提交或发布。命令定义检查与运行证明分开。

## 找到影响项目取舍的事实

确认指定路径或当前路径的项目根、适用指令和已有改动。路径无法确定目标时只澄清该问题。
先沿实际 Agent 入口、技能索引和相关模块指导，找到现有测试策略归属、技能目录惯例及执行
交接方式。职责匹配才合并；运行诊断或视觉验收技能仍由原 owner 负责，多轮验证接续沿用
现有工作记录和必要方法，不因适配策略新建平行流程。

从本次适配涉及的真实变化、合同或已知故障找出需要判断的失败，再按判断所需读测试、配置、
脚本、CI 或模块文档。例如，已有逻辑测试能否触及客户端接线，要看实际调用与测试边界；
不能仅按技术栈名推断。阅读服务于这些选择，不要求全仓 inventory，也不为每个模块编造风险。
尚无测试规范时，从已知输入输出、退出码、副作用等实际合同建立最小判断，未知保持未知。

核实会让后续 Agent 行动的具体位置：期望依据和现有用例在哪里、相关验证命令如何定义、
从哪个目录运行、需要什么环境与权限、证据通常落在哪里。配置存在只说明有定义，不说明
可运行。缺命令、缺环境或无现行记录方式时明确指出，不用示例命令或虚构流程填空。

## 把事实写成项目方法

用项目事实实例化主技能的保障比较，形成后续变化仍可使用的取舍理由，而非复制通用规则后
附一张工具表。说明本项目哪些失败通常由现有保障揭露，什么接合或条件容易遗漏，何时维持、
修复、补充、替换或暂缓；将漏检后果、诊断和维护负担一起纳入理由。无需凑齐所有结论。
已有权威文档包含有效判断时直接引用，把新增判断放在缺口处。

例如，若检查确认 CLI 逻辑测试覆盖参数规则，却没有观察真实进程退出码与文件写入，
本地方法应说明何种变化复用逻辑测试、何种变化需要进程边界观察，以及当前未覆盖什么。
这只是适配思路，不能写成目标项目已有这些测试或命令。对没有成熟流程的项目，给出基于
实际位置的最小行动路径；不创建行为库、CI 门禁或成熟工作流的假象。

将必要保障接在对应选择上：项目要求的精确协议或文本、替身隔离、各客户端集成观察，不能
因看似脆弱或重复被抹去；已有分级、覆盖目标和发布条件保留其效力与依据。源项目的门槛与
工具偏好不自动成为目标约束，通用方法也不构成禁止合理本地约束的理由。

本地方法须使后续 Agent 能找到稳定的期望依据，并据实际行为区分测试漂移、产品缺陷与
经授权的语义变化；不能一见定位失败就修到绿。按实际需要保留行为说明到自动化、回放或
知识复用的关系，说明实际观察才支持通过结论。清理继续比较保障与替代，不另建治理流程。
对暂缓或受阻部分写清失败窗口、理由与重议条件。

将所选观察与已核实的路径、命令、运行目录、参数、环境前提及结果位置接在一起，必要细节
可放本地 reference。标明命令仅检查过定义，或准确引用已有运行证据。后续已授权补测、修复
和复测要交到实际执行入口；没有专用工作流时说明按正常开发推进，不让策略职责成为停工理由。
费用、真实数据、副作用、服务启动和人工观察等边界沿用目标指令。

## 写入可独立维护的载体

优先定向合并职责匹配的本地技能。没有匹配项时，沿用项目目录与命名习惯创建专用技能；
本地技能须使用可区分于通用技能的名称；在可行范围内核对项目已有技能及当前可用通用技能
的名称，发生同名冲突时选择带项目限定的名称，不按路径顺序静默覆盖。若连技能目录也没有，
且宿主没有其他约定，可在 `project-testing` 未被占用时创建
`.agents/skills/project-testing/SKILL.md`，配所需的本地 references。采用宿主要求的
frontmatter，确保其中的 name 与技能目录名一致；没有额外约定时至少写明名称、触发
与职责边界。实际落地后使用真实路径，不留下骨架或占位项。

本地技能应包含可行动的项目取舍、期望维护方法和执行接续关系。必要方法与资源随产物提供，
不能只是“先读通用技能”的 wrapper；隐藏通用来源后仍须可用。来源可作简短说明，不能成为
安装、访问或运行依赖，也不要求出现源项目名称。本地版本由项目维护，无强制同步关系；
候选判断保留候选状态，不因生成文件宣称成熟。不将这次静态审查的过程史写进长期方法。

## 按职责合并并接入实际发现路径

重跑先读当前本地技能、references、发现入口及人工修改，对照此次来源变化和项目依据，
只合并有依据的部分，不整份覆盖或重置，也不另建重复策略技能。保留有效的项目决定；
冲突无法消解时保留现状，具体报告双方依据与未合并部分，继续完成独立确定的部分。
只有影响取舍且必须由用户决定的冲突才提问。

沿现有发现链添加或更新最小触发与本地链接：根入口已路由到索引时更新对应索引即可。
多个实际宿主消费者确实各有入口时，维护它们必要的路由，不能为了“唯一入口”留下失联
消费者；也不把方法正文复制到各入口或创建所有宿主配置。完全没有发现入口时，创建只含
必要触发与技能链接的最小根 `AGENTS.md`。保留无关指导及其他技能职责。

## 静态交付

核对实际变更范围、frontmatter、触发与发现链，以及新增或修改的相对资源链接能否从所在
文件解析。检查引用命令的定义、目录与参数，清掉未填骨架、占位路径和虚构命令；必要未知
明确保留。在 Git 项目核对 status、diff 和空白错误，保留无关工作。本模式不执行所引用的
产品或测试验证命令来证明适配有效，也不自动做测试或产品改动；上述 Git 与链接等静态检查
仍须完成。

交还生成或合并的文件与发现入口、支撑项目取舍的依据、保留的本地决定和冲突、静态检查
及剩余未知。明确指导适配不等于命令运行、测试通过或技能激活效果得到验证。
