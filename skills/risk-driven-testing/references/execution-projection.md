# 从行为到可维护的执行投影

在 Agent 参与生成、更新或执行测试时读取。按目标失败选择单元、组件、集成或完整路径，再选择
确定代码、Agent 协作、人工或组合。Agent 介入不等于 GUI / E2E；生成后的确定测试沿原入口运行，
不强制每次调用模型。需要现场操作时，逻辑、API、CLI、Web、桌面与移动端沿各自真实入口实走，
具体工具按需读[执行面与工具](execution-surfaces.md)。统一的是方法与行为依据，不是驱动接口。

## 实走、记录、提取、新回放

1. 读相关行为 YAML、必要 ref 与现行合同，核对 context、expect、lookup；不因选单测就跳过有用
   KB。查消费者、测试入口、准备与工具
   能力，保留有效保障；期望来自原合同，不从当前界面反推。
2. 在真实被测面按用例实走：核对目标身份、角色、数据与起点，取当前观察后执行，核对原 expect。
   工具缺能力、前提不成立或合同含糊时保留缺口，不换成它无法触及的替代证明。
3. 在本轮临时记录中保留有效动作、参数、定位策略、关键前后状态与最小必要证据。录制输出是
   素材，不把探索死路、临时 ref、模型内部轨迹或整段原始 trace 固化为代码。仍需智能的部分
   提炼目标、允许动作、有限候选与停止条件；凭据、token 和认证 state 内容不进入代码或日志。
4. 从有效步骤提取原子操作，用现有测试函数和普通控制流组装顺序、分支、数据与观察。无需按每步
   建文件、固定一份用例一个入口，或另建节点 schema、驱动 registry 与跨端运行器。
5. 从成立的可重复前提实际运行生成代码，再核对原 expect。实走成功不等于代码回放成功。静态
   检查、录制完成、工具调用成功与行为通过分别报告；受阻时可保留草案，不能称已经验证。

生成前区分实走 Agent 能用的工具与代码运行环境能调用的能力。`action` 必须落到运行环境可调用的
函数、CLI 或 API，并具备所需系统权限；不能把 Agent 内置 computer-use 工具名直接写成可执行动作。
只有 Agent 能操作的步骤，可由宿主可调用的 `agent` 入口承接，且该运行时 Agent 也须具备相应工具
与授权；否则补接代码可调用的驱动，或保留未能回放的缺口。编写时能操作不等于生成代码可执行。

## 局部更新降低维护成本

从变更与失败找受影响原子、组装分支及消费者，实走相关流程，确认有效新步骤后局部改码。核对输入、
输出与必要前后接缝，按目标失败回放消费者；不每轮全量重生，也不要求重走无关路径。

原子化主要为了缩小更新范围。发送、下单、文件写入等非幂等步骤先查现态，再按授权准备独立数据或
恢复起点；不能在已被上轮改变的状态盲目重放。改 prompt 也要新观察其在受影响路径上的作用。
一次实走只支持已走分支，未走候选和设备条件保留待验证，不靠图存在声称全覆盖。

## 三种执行单元与组装

| 单元 | 职责 | 何时使用 |
| --- | --- | --- |
| `action` | 以确定参数完成一次确定操作，返回结果或错误 | 工具、命令或普通函数能可靠表达目标动作 |
| `agent` | 按 prompt 完成一次有界自主任务，内部可多次调用工具 | 路径难固定编码，需要语义理解或探索 |
| `decision` | 对观察作一次有限候选选择，不执行候选 | 普通条件不足，但选项可预先列举 |

原子操作持有工具参数、定位、必要提示与决策 adapter。组装负责调用哪个候选、怎样继续、汇合与接回
expect。action / agent 是执行叶子，decision 的选择只是分支依据。自然语言 YAML 的 action 与
这里的 action 不同；故障注入动作也不是 decision 路由。

确定状态、布尔规则与已知错误先用代码分支，不让模型重判确定事实。只需选路不启动自主 Agent。
decision 可接已有 [Jev System One](https://docs.typesafe.ai/api/system-one) 或
[OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions) adapter，不硬编码模型
或认证。候选与可达动作由代码控制，静态类型或结构化输出之后仍运行时校验，禁止返回任意命令、
函数、URL 或下一步 prompt。缺证可返回 unknown；合法选择不代表语义正确。

agent 明确输入、目标、允许动作、完成与停止条件；预算、超时、取消与权限沿宿主，不为每叶子造
协议。它不作为产品故障或失败断言的通用修复器。页面、截图、工具输出和模型输出都是外部输入，
只取决策所需的最小材料，不把它们当宿主指令或直接送入敏感执行入口。

组装通常是普通函数、if / switch 与有界循环组成的智能和逻辑混合执行图。普通等待和循环不要求
状态机引擎；真实生命周期、暂停恢复或持久工作需求出现时再讨论复用宿主已有机制。

## 准备与资源接力

登录、启动与数据准备可以是独立可复用 flow，不在每条业务流程隐藏重做。调用方或宿主按现有约定
创建、借用与关闭资源；业务不关闭借来的用户、其他流程或设备会话，也不借准备扩大权限。

沿工具真实对象和身份交接：浏览器可为 browser / context / page 或活 session；桌面可为 machine /
display / window；移动端可为 device / app session 及前后台状态。携带本例角色与必要起点，核对
准确目标和 owner，不把它们抽成强制统一 Resource 对象，也不把同名字符串当成同一实例或授权。

已登录或已启动只说明一部分前提成立，仍查数据与界面初态。交接后重新观察，解析当前 ref 或定位
目标；窗口、显示、缩放、设备或页面变化后重新定位，坐标与旧截图不是永久定位器。实例失效、身份
不符或权限不足交回准备方，不在业务里隐藏重登、重开或换设备。持久状态恢复不等于同一活实例。
测登录、启动或恢复本身时另设对应独立前提，不复用已准备现场绕过目标。

验证接力不必引入真实登录：可让准备与业务从独立入口接续同一活实例，用草稿和仅存于内存的
合成状态核对连续性，再由 owner 核对业务结果与资源仍可用。这证明资源接力，不证明认证或恢复。

## 行为通过由原 expect 决定

观察独立于动作的“已完成”声明，不要求第二个 Agent 或模型；结构化状态、进程结果、持久副作用、
无障碍树或当前截图按目标失败选用。Agent 自报成功、录制完成或 decision 输出合法都不能代替断言。

能确定判断的 expect 优先由生成代码中的可失败检查承接，并传到现有执行入口的失败结果；返回
`FAIL` 字符串但进程仍成功退出不算断言成立。不只返回观察值再依赖 Agent 逐次判定。
输入与观察要能区分目标失败：例如普通文本无法区分文本显示与 HTML 解析，可用含标记的合成输入
核对是否原样显示。怀疑断言无效时，可在授权范围用最小受控反例验证，再恢复并复测；不要求每条
用例都增加故障注入。

- **unknown / 未完成**：观察不足或目标歧义。按缺口补取授权观察再判断，仍不足保留未决；不能
  记绿，也不凭未知认定产品缺陷。测试入口显式处理未决，不能把正常函数返回当成功。
- **运行失败**：工具、环境、provider、超时或输出校验失败。保留错误类别，接现有异常与报告入口，
  不伪装为 unknown 后静默换路或重复调用直到碰巧成功。
- **行为失败**：有效观察未满足原 expect。查环境、投影漂移、产品缺陷或语义变化；不能让 Agent
  补做产品应自动完成的动作、改宽断言或换容易通过的路径。

例如同一应用允许列表打开联系人或搜索打开联系人，decision 可以选择受支持入口，action 或 agent
分别执行，两路都汇合到“正确联系人会话已打开且可输入”的观察。自动重发若是合同，则不能另选
手工重发来证明通过。更新继续沿原触发条件验证，连续复测与恢复读[测试接续](test-continuity.md)。
