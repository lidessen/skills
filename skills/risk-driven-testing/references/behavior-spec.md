# 稳定行为规格与 YAML 用例

在保存或维护业务行为 KB 时读取。YAML 的知识价值独立于测试层与执行安排：单测足够、不做 GUI、
暂不生成代码都不是省略或删除有用 YAML 的理由。背景、动作、期望与关联仍按 story / feature /
case 模型维护；简单规则可以保持简式。不因采用 YAML 就强制 E2E、固定配额或执行 DSL。

## 行为比执行表达更稳定

用背景、前提、动作与可观察结果表达合同。定位器、坐标、窗口引用、驱动参数和模型提示属于投影；
URL、协议字段、精确文本若本身是合同，仍保留必要精度。不可从本次产品输出反推正确期望。

按 story（任务主流程）、feature（能力合同）、case（边界或异常）组织：主干步骤进 story，
主线装不下的窗口独立为 case。它们是阅读组织方式，不规定目录、层级字段或测试数量。沿目标项目
已有布局维护可追溯关系，不要求一份 YAML 对应一个 spec，也不为每个执行原子创建用例。一份
YAML 可由多个已有单元 / 集成保障承接，或暂作不执行的 KB；生成哪层代码由真实保障缺口决定。

```yaml
id: direct-chat
description: 用户打开 Alice 的会话并发送消息
context:
  - 用户已登录，Alice 是唯一匹配的测试联系人
  - 本例从会话列表开始，消息文本为无敏感内容的测试数据
steps:
  - action: 打开 Alice 的会话
    expect: Alice 的会话已打开，消息输入框可用
  - action: 输入消息并发送
    expect:
      - 同一条消息显示为已发送
      - 输入框清空
lookup:
  - 消息发送入口与发送状态转换
  - 会话输入组件的发送处理
```

### 字段与投影的关系

- `id`：用语义短名作为阅读和投影追溯锚点，在选定行为库中避免歧义，沿项目已有命名约定。
- `description`：说明这份行为材料负责什么。
- `context`：背景、前提、资源取得方式。可以声明已登录或应用已启动，由独立准备 flow 接回；
  不复制真实凭据，仍核对本例角色、数据和起点。
- `steps`：自然语言 `action` 与可选 `expect`。一个行为动作可由多个执行操作实现，动词不构成
  可执行枚举；执行层 action / agent / decision 不加入这里。
- `expect`：来自需求、协议或有权确认的行为基准，可以是字符串或列表。空缺表示没有额外断言，
  不能据此声称整个行为已验证。
- `lookup`：给 Agent 的自然语言查找线索，不是固定源码绑定。

项目需要时可沿用 `status: manual | automated | stale | obsolete` 表示执行安排的就绪状态。
它不等同于 GUI / E2E，不注册 CI、不授予模型费用或工具权限，也不是本轮通过证据；KB 暂不执行
时可不填，项目已有等价状态时不再建一份。

## ref 是阅读弱引用

下面节选自示例 `features/send-message.yaml`，ref 相对该用例文件，不相对本文：

```yaml
id: send-message
description: 消息发送能力
context:
  - 正常发送与断线重发分别有行为说明
steps:
  - action:
      ref: ../cases/offline-resend.yaml
    expect: 恢复网络后自动重发同一条消息，不重复发送
```

`ref` 表示其他行为材料与这里有关，供 Agent 按需阅读；不复制内容、不继承前置、不递归生成执行边，
双向引用合法。引用处已写的 expect 仍须核对，不能因为 ref 不执行就丢掉行为要求。生成投影时说明
哪处实际观察守住它；缺少前置或观察条件时保留缺口。

示例使用相对当前文件的路径；较大行为库也可按已声明的库根给完整相对路径。相对路径与符号链接
不得越过授权阅读范围；歧义或目标缺失先报告，不靠静默挑选任意 story 消解。不把 ref 变成执行器
输入，也不把引用可解析当成行为通过。完整可读例子见 [chat story](examples/chat/story.yaml)。

## lookup 是查找资料，不是固定路径断言

组合使用业务概念、符号、现有测试行为与粗粒度目录定位当前实现。路径可以作线索，但不把它变成
正确性的唯一锚点；重构后应能用其余线索重查。具体定位结果留在本轮工作记录或已有投影里，避免
让稳定行为随每次搬文件更新。

单条线索失效不直接使行为失败；全部失效或存在歧义时先查当前合同、调用与变化。定位失败可能是
测试表达漂移，也可能是按钮误删、权限回归或产品缺陷，不能自动修到绿。行为语义真的变化时先由
有权负责人确认，再同步期望与执行投影。

维护和验证投影时读[执行投影](execution-projection.md)；格式与引用用项目已有解析或静态检查
核对即可，不为这套阅读材料另建通用编译器或校验框架。
