# Architecture · 整体架构与组织设计

使各部分在明确的责任与关系下共同完成整体目的，并能随实践发展。架构的对象是那些
影响整体的选择：怎样分工，怎样接合，谁有权决定，哪些变化需要一起发生。目录、技能
分类和组织图只是表达；每部分都合理，不代表它们组合起来仍能完成工作。

## 从整体目的与现实矛盾出发

恢复服务对象、要达成的结果、已确认承诺和当前压力。区分根本目标、现有路线与偶然
安排；现状不能自动证明必要性，外部模式也不能代替自身判断。新设计先找真实需求，
已有体系 review 先找它实际服务的工作，而不从部门、模块或技能名称反推用途。

局部任务只恢复会影响判断的邻接关系。全体系 review 则先建立覆盖范围与轻量关系图，
再逐块深化，同时保留跨块链路的核对；不要将全量要求缩成几个方便的样本，也不为了
完整重建全部历史。优先处理决定整体效果的矛盾，不把所有局部偏好升格为架构原则。

## 恢复责任、权力与实际关系

按当前对象辨清：每部分承担什么，输入输出给谁，谁拥有权威事实与资源，谁能决定、
执行、接受结果和处理失败。标明实际观察、正式约定、候选设计与未知；一个名义 owner
没有对应能力、资源或授权时，责任并未落实。

区分职责、依赖、信息流、控制或决策、资源和生命周期。需要一起变化的内容不一定
需要同一个容器；放在一个容器内的内容也不一定共享权力与状态。领域不同，成立依据
不同：软件可由接口和运行机制约束，技能依靠发现与选择，人的协作还取决于沟通、
能力、动机和被接受的权责。不能凭类比宣称软件隔离、技能引用或组织治理已经成立。

## 组织整体，而非平均分配局部

按真实变化原因、协作频率、知识与资源分布划界。比较保留现状、合并、拆分、调整接口
或决策位置的实际代价；选择能支持需求的最小安排，不因可拆就新增层级、委员会、
服务或协调者。集中便于统一承诺，分散便于贴近信息，判断哪种决策需要哪种安排，
不用一个原则覆盖所有关系。

沿关键工作从输入追到最终结果，核对交界处的接纳、反馈与接续责任。谁判断局部结果
够不够，谁处理跨部分冲突，延迟或失败时谁能继续工作？正式接口之外的绕路和补偿
也属于现状证据；如果整体依靠别人重复录入、人工追踪或默契兜底，不能只报告图上分工清楚。

比较整体承担的负担：一处简化是否让另一处更难，一处效率是否降低整体完成能力，
新增统一层是否夺走必要的局部判断。必要复杂度可以保留；可行选择有分歧时给出决定
及理由，不用职责表或架构图代替取舍。缺少会改变方向的用户目标或授权才请求决定。

## 在变化与实践中检验

选择会改变方案的正常、冲突、失败或变化场景，推演各部分怎样合成最终结果。尤其
检查新增消费者、责任转交、资源短缺与目标变化是否让边界失效。按风险做最小验证；
推演、机械检查、实际观察与接受分别报告，不把漂亮结构或各块通过当成整体成立。

设计新体系时说明怎样从最小可用安排发展；重组已有体系时说明过渡期间谁承担原责任，
哪些身份、资料、承诺或未完成工作必须保留。沿已有 owner 和权威位置修改，不新增
第二套事实或永久总控来方便本次 review。设计组织不自动授权调整人员、发布制度，
设计产品也不自动授权部署或数据迁移。

交付让读者能重建选择：整体目的与当前压力，关键责任和关系，主要矛盾与替代方案，
推荐安排及代价，接合与演进方式，证据和未决问题。结果可以是有理由地维持现状；
不强制套图、评分或固定数量的层级与候选。

## 按对象深化

- 代码库、目录、模块、构建与运行边界：读 [代码库设计](references/codebase-design.md)。
  混合语言、语言惯例和更细边界判断由该文按需展开。
- 整套 skills 的定位、覆盖、引用与归属：读 [技能体系设计](references/skill-systems.md)。
- 团队、岗位、长期协作与决策组织：读 [组织设计](references/organization-design.md)。

只读当前对象所需的参考，不把不同领域统一成同一种边界或强制分层。

## 与相邻方法接合

本方法检查整体关系与体系覆盖，主 Agent 仍对当前任务综合负责；它不是所有设计工作
的前置审批。已有证据足够作出安排或局部修正时直接完成，不因问题跨了一个边界就
另起流程。只有下列专门判断仍未解决时，才按需深入相邻方法：

- 技能或 prompt 是否值得存在、如何表达与激活：使用 [agent-guidance](https://github.com/lidessen/skills/blob/main/skills/agent-guidance/SKILL.md)。
- 既有设计被补丁和局部机制带偏，需要反例与减法比较：使用 [design-forge](https://github.com/lidessen/skills/blob/main/skills/design-forge/SKILL.md)。
- 已选责任安排下的重复、残留和错位整理：使用 [defrag](https://github.com/lidessen/skills/blob/main/skills/defrag/SKILL.md)。
- 大体量工作如何分治、协调并整体验收：使用 [divide-and-conquer](https://github.com/lidessen/skills/blob/main/skills/divide-and-conquer/SKILL.md)。
- 外部理论或方案的成立条件与吸收判断：使用 [research-synthesis](https://github.com/lidessen/skills/blob/main/skills/research-synthesis/SKILL.md)。

带入整体目标、局部问题、有效承诺与已有证据，带回会改变整体判断的结果；链接不自动
启用、不扩大权限，也不要求每个任务加载整套方法。相邻方法缺失时仍可交付当前架构
判断与具体缺口，不靠无限转向回避决定。
