# 视觉评审与对照

## 先评整屏，再评组件

按对结果的影响选择视角，不必逐项出表或打分：

- **构图与主次**：缩小看或眯眼看，第一、第二视觉落点是什么？它们与主要任务一致吗？页面中最大的区域是否承担最重要的内容，还是让导航和容器占据中心？
- **空间表达**：接近、对齐、尺度与层次是否已经表达内容关系？哪些边框只是补救分组不清？不同层级是否被相同卡片抹平？不要为了变化而破坏本来有意义的重复。
- **字体与节奏**：标题、正文、注释的角色和比例是否清晰？真实文字长度是否适配？疏密是否有节奏，还是处处等距、同重、同大小？分别考虑实际语言文字与数字。
- **色彩与材质**：强调色在表达重要性、交互状态还是仅作装饰？明暗与层次是否有秩序？气质由结构、排版与细节共同形成，换一套配色不能单独成为设计方向。
- **产品特征**：替换产品名后，这个画面是否仍能无差别套给另一个产品？哪一个核心内容或动作值得成为有记忆点的表达？操作型界面也可以靠精准、克制形成特点。
- **交互的视觉连续性**：一个完整动作里，焦点、上下文和依据怎样显露、移动或退场？若要自动移动视角，说明得到什么、牺牲什么；动画数量不等于交互品质。

每个发现都写清“看见了什么 → 为什么影响实用或美观 → 应改变哪种空间/表达关系”。
“字号太小”不足以成为方向；“导航占据视觉主位，核心内容像辅助注释”才触及层级。
分清可观察事实、解释和审美偏好。保留有作用的特点，不用禁止某种字体、圆角或颜色来代替判断。

## 从不协调定位到改变

看到拥挤、松散或尺寸不一致时，先判断哪种关系失效，再决定改哪里：

- 内容本来属于同一组，却被间距、边框或重复操作切碎：先调整分组与操作范围。例如连续回答可共享组末复制入口；是否合并由内容关系决定，不由数据条数决定。
- 分组清楚，但文字、控件与图标互相争抢：以当前阅读文字为参照，比较字面、行高、控件留白和视觉重量。协调不要求同字号，也不把所有属性同比缩小。
- 单个组件协调，放进页面后失衡：检查相邻组件、容器宽高、对齐和滚动关系，避免用组件内部补丁修页面构图。
- 声明的尺寸或主题与画面不符：查看最终生效样式和覆盖来源，再判断应修组件、主题还是应用覆盖。设计评审说明视觉后果与修正层级，不扩展成无关架构审计。

这些是转向线索，不是必经检查顺序。统一应保留有意义的区别：组内靠近、组间停顿，主要内容与辅助过程具有不同重量；同角色协调，不同角色可辨。密度的目标是支持阅读与行动，不是处处等距或一律紧凑。具体像素与平台惯例都需服从当前情境。

按疑问选择观察工具：原始界面看主次、阅读与操作；分类标注查实际尺寸、文字或间距，一次聚焦当前疑问；[元素色块抽象](image-diagnostics.md)看空间分布、对齐和重心。回到原界面核对诊断，不要求每轮使用全部工具，也不以数值一致或色块均衡代替设计判断。

## 比较具有实质差异的方向

当构图本身需要重审时，先提出少量有意义的替代方案，再挑细节。通常两到三个方向足以比较，
不要为凑数制造弱方案；单一明确问题无需强行发散。

每个方向先用一句话说明空间主张：主角是谁，用户沿什么顺序理解，辅助信息如何进入。再提供可看见的整屏草图或高保真对照；用户要求交互时，演示同一段关键操作。
文字与 ASCII 草图只能验证空间思路。用户要判断审美效果时，至少把推荐方向呈现为含真实文字、字体尺度与色彩的可查看画面；未做到时标记为构图提案，不宣称视觉方向已验证。
实质差异来自阅读顺序、空间组织、对象表达或状态转换。字号、色相、阴影变化不能冒充方向差异。

对照使用相同核心内容、相同视口与相同任务状态；示意数据标明用途，不能把虚构内容呈现为产品事实。
不能为了让新方案好看而减少困难内容、藏起长标题、删去来源或移除已要求的功能。窄屏有需要时重组内容优先级，不能只把桌面同比缩小。

写明每个方向带来的收益与代价，明确推荐一个，并指出什么反例会改变推荐。
不要把各方向最醒目的局部拼成缺少整体逻辑的折中稿。

## 组件库与展示工具

用户要求完整覆盖时，从实际公开组件、有限样式变体与可选内容区域核对样例；组件“在某页出现过”不代表其头像、长名称、禁用或另一尺寸已有可检查的画面。优先补会改变构图或操作关系的样本，不穷举任意属性组合，也不把一次走查清单变成永久门禁。

样例承担不同判断：样式对照适合稳定排布，真实活动适合可操作的完整片段，图标目录应让人快速辨认与选择。说明为当前判断服务，不能用哲学标语或密集测试标签挤掉对象本身。展示工具的导航、工具栏、画布、反馈也要有主次和连续性，不能因为它是内部工具就免于视觉评审。

样例正确而实际页面不协调时，沿问题涉及的路径对照独立组件、组合场景与真实应用。核对承载宽高、真实长内容、滚动归属、主题和输入方式；展示外壳制造的额外留白或双滚动不能直接归因于组件。只检查会改变判断的场景，不要求每次遍历全部页面。缺少真实应用时，明确结论只覆盖样例。

把“有样例”“状态可操作”“画面经过判断”分开记录。样例补齐后，在相同内容与视口下观察主题和明暗差异，选出最破坏整体关系的地方继续制作与复看；功能和对比度合格不自动代表比例、节奏与材质已成立。沉淀 skill 改动时记录哪个实际观察改变了判断；没有对照证据，不宣称改写指令造成了审美提升。

## 复核已确认的选择

后续调整触及用户已确认的比例、分组或操作关系时，从当前任务上下文或项目既有记录恢复选择的理由和适用范围，重走原来暴露问题的片段。平台适配、主题切换或组件替换若改变了这些关系，应比较新收益与旧问题是否重现；不能仅以惯例或代码复用证明视觉改善。

已确认选择可以修订，但需说明新证据和代价。保留可迁移的理由，不把某项目的字号、按钮高度或间距写成通用默认，也不为此另建决定台账或永久验收门禁。修改后区分样式数值已确认、实际行为已观察和用户已接受；只核对源码时，保留视觉效果未验证的边界。
