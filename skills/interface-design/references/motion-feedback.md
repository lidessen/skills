# 动态与反馈：变化怎样成为可理解的语言

2026-09-21。这是研究支持的设计方法与待试验建议，不是已落地的组件合同。反馈包含文字、形态、位置、声音或触觉；动画只是其中一种表达。

## 实践来源与边界

[Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：读取目的、反馈、可取消与可选动态相关正文。平台建议运动跟随操作预期，简短准确，避免高频操作反复付出动画成本，并允许中断。它是实践规范，不是某个时长最优的实验。

[Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)：读取交互、动画与设计段落。其准则强调因果、可中断、明确动画属性、减少动态替代，以及加载时保留标签。其中延迟显示与最短展示时间是防闪烁建议，不能拿来人为延迟已完成的结果；文档自身的框架、对比算法等偏好不直接成为本项目规范。

## 理论证据的不同强度

- [Nielsen：Response Times](https://www.nngroup.com/articles/response-times-3-important-limits/)，读取正文与补充。它是经验综合，区分即时响应、等待与注意转移。常见的 0.1/1/10 秒只是近似尺度，不是动画时长标准。
- [Heer 与 Robertson：Animated Transitions in Statistical Data Graphics](https://sites.stat.columbia.edu/gelman/communication/HeerRobertson2007.pdf)，读取 §3.2、§5、§7。24 人的图表实验支持特定追踪和变化判断任务中的动画收益；迁移到面板或列表仍需检验，不能推导所有变化都该动画。
- [Iqbal 与 Horvitz：Disruption and Recovery of Computing Tasks](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/CHI_2007_Iqbal_Horvitz-1.pdf)，读取摘要、方法、恢复行为与讨论。自然工作观察提示中断与恢复线索的重要性；关联不是对所有通知形式的因果结论，也没有固定的“每次中断损失时间”。
- [WCAG 2.2 hover/focus](https://www.w3.org/TR/WCAG22/#content-on-hover-or-focus) 与 [交互动画](https://www.w3.org/TR/WCAG22/#animation-from-interactions)，读取相关条款及 motion 定义。前者 AA 对附加内容有可关闭、可进入与持续性要求及例外；后者 AAA 处理非必要运动的关闭能力。规范不禁止全部 hover 或动画，也不等于审美评分。

## 表现力：形变、光影与运动共同建立质感

用户明确重视动态带来的高级感，因此不能把动画价值收窄为信息传达。“高级感”是待通过体验判断的审美目标，不是统一可测物理量。

[Apple：Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/)，读取演讲中连续性、手势初速度、重定目标与性格选择部分。位置连续之外，速度衔接也影响手感；弹簧可以没有可见回弹。具体 API 的预设并非所有媒介的通用解。

[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 的 Dynamics 文字把形态、光学效果与运动放在共同设计中；[Sharon Harris 的 Material 动态回顾](https://design.google/library/material-design-motion-sharon-harris)说明动效也承担情感与表现力。这些是实践者说明，不是“玻璃更高级”的实证。

由此提出以下表达实验，而非已确定规范：

| 表达维度   | 可以探索的关系                                 | 观察重点                                       |
| ---------- | ---------------------------------------------- | ---------------------------------------------- |
| 形变       | 按压与局部压缩、释放与恢复；轮廓和内部内容协调 | 是否有接触感，文字是否被不必要地拉伸           |
| 光影       | 高光、阴影、边缘明暗随同一层次变化             | 是否像同一个物体，而非各属性独立闪烁           |
| 重量与弹性 | 启动、超调、阻尼和收敛表达不同性格             | 精密还是松散，轻盈还是拖沓；不等于回弹越大越好 |
| 连续性     | 从当前形态与速度接续新的输入                   | 连点、反向、中途松手时是否跳变或重播           |
| 编排       | 主体先响应，辅助细节随后收敛                   | 是否有整体节奏，操作是否被等待锁住             |

例如同一个按钮：平面配方以色阶和边缘变化回应；柔性配方以局部形变和无明显弹跳的恢复回应；空间配方协调表面、高光和阴影。三者都可以追求精致，不能把高级感直接等同于玻璃、强阴影或大量形变。

表现性动效可以以愉悦、触感、身份为理由保留，不强迫每段动画证明效率收益。与之对应的证据应是实际观看、操作与审美比较；频率、幅度、性能和输入连续性仍然影响最终体验。

## 先定义反馈的含义

下表是本研究的设计推论。状态不是一条必经流水线：focus 可以与 hover、pressed 或 pending 共存；不同控件只使用适用状态。

| 发生什么            | 人需要知道什么             | 可探索的表达                         | 不能混淆                             |
| ------------------- | -------------------------- | ------------------------------------ | ------------------------------------ |
| Hover               | 指针指向哪个可操作对象     | 局部底色、轮廓或文字对比变化         | 未选中，也未触发；触屏不能依赖它     |
| Focus               | 下一次键盘输入作用在哪里   | 持续可见的焦点标记                   | 不用 hover 代替焦点；不自动执行      |
| Pressed             | 控件感知到正在按下         | 立即局部加深，必要时轻微形变         | 不代表请求已接纳或成功               |
| Selected / expanded | 哪个选择或结构状态正在生效 | 稳定的标记、位置或表面区别           | 指针离开仍保留                       |
| Pending             | 操作已开始，结果尚未确定   | 保留对象与动作含义，给出真实进行状态 | 无限转圈不解释阻塞；动画不能伪造进度 |
| Success             | 哪个结果已经成立           | 就地结果变化；必要时短暂确认         | 请求接纳不是整个 Agent 工作完成      |
| Error / blocked     | 什么没完成，怎样继续       | 对象附近明确说明，保留输入和恢复入口 | 不能只闪红或抖动后消失               |
| Enter / exit / move | 对象从哪里来、去了哪里     | 有锚点的淡入、位移或尺寸变化         | 对象变化不等于全屏都要动             |

反馈还要区分位置：对象内反馈解释局部变化，任务级反馈说明较长工作，跨项目通知用于需要介入的事件。避免同一次成功同时用按钮变色、toast、横幅和弹窗争夺注意；是否冗余取决于实际接收需求。

## 参数化的是运动性格，稳定的是状态含义

可形成 motion 配方的参数包括：响应延迟、持续时间、曲线或弹簧、位移、缩放、透明度、变化起点、连续操作的衔接方式。弹簧还需考虑初速度和收敛；不必强行换算成一个固定 duration。

先按用途命名，如局部响应、层次切换、对象移动、持续进度；再为配方选择数值。持续等待由真实任务决定，不应绑定到固定动画时长。没有证据支持全产品统一 200ms，或者所有按钮都缩放到 0.98。

精密工具可以偏向局部色阶与短促收敛；温和编辑可以使用柔和淡变；空间语言可以强调来源与连续变形。这些是待比较配方，不能让风格改变成功、失败或焦点的含义。高频工具动作和低频庆祝表达可以有不同节奏。

## 验证动态必须覆盖时间

截图用于验证静态状态，无法证明过程中是否突兀、可中断或导致等待。下一轮 Meowbook 动态场景应观察：

- 指针进入离开、按下后移出取消、键盘操作、无 hover 的触摸输入。
- 快速成功、较慢处理、失败、取消；快速连续操作时旧动画不排队拖住新意图。
- 展开后立即关闭、切换后返回，位置和焦点可恢复；不能要求人等动画结束。
- 减少动态时，保留同等信息，可使用直接状态切换或适当淡变；不是统一把所有动画时长乘零。
- 密集真实内容下，动效不使文字发虚、布局跳动或持续夺走阅读注意。

这些是后续场景建议，本轮尚未实现录制、时间控制、网络状态模拟或自动动态验收。性能指标、可访问性合规、主观手感与用户理解分别验证，不合成一个“动画通过”结论。
