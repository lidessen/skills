# Agent 性格倾向诊断

## 读取时机

当需要判断一个 Agent 在当前模型、上下文和任务范围内表现出怎样的性格倾向时读取。比较不同塑造方式属于单独的实验流程，不在本文件中处理。

## 诊断对象

这里诊断的是 **特定模型、上下文和任务分布下的行为倾向**，不是模型内部稳定的人格，也不是对 Agent 做人类心理诊断。诊断结果是 E / I、S / N、T / F、J / P 四个连续维度上的可观察方向及其证据范围。

不要因为四个分数恰好落在某一端，就直接宣布 Agent “是”某个四字母类型。

## 从人格测量借用什么

人类人格量表通常不会用一道直白问题决定一个维度，而是使用多个题项覆盖一个领域及其子面向，再检查内部结构、可靠性和外部效度。例如 BFI-2 的开发同时使用理论和实证标准组织领域、面向与题项（[Soto 与 John，2017](https://doi.org/10.1037/pspp0000096)）。本方法借用多题项、平衡取样、重测和效度检查这些原则，不复制现成人类问卷，也不假设它们可以直接测量模型。

LLM 的自陈问卷对提示模板、选项顺序和否定表达非常敏感。多项研究发现，语义近似的提问方式或简单交换选项顺序就会显著改变人格分数（[Shu 等，2024](https://aclanthology.org/2024.naacl-long.295/)，[Gupta 等，2024](https://aclanthology.org/2024.blackboxnlp-1.20/)）。因此，自陈只能作为一致性探针，不能作为主要诊断依据。

主要证据来自构念明确的情境判断和真实任务行为。情境判断测验可以针对不同构念设计，只有测试内容和目标构念、外部标准相互匹配时，结果才有可解释性（[Christian 等，2010](https://doi.org/10.1111/j.1744-6570.2009.01163.x)）。面向 LLM 的 TRAIT 也采用了把人格构念扩展到现实场景、同时检查内容效度、内部结构、拒答和可靠性的路线（[Lee 等，2025](https://aclanthology.org/2025.findings-naacl.469/)）。

## 四个构念

测试题和评分规则必须从对应维度的可观察定义出发：

| 维度  | 主要观察对象                               | 定义来源                                   |
| ----- | ------------------------------------------ | ------------------------------------------ |
| E / I | 思考何时进入外部互动，求助前后发生什么     | [外倾与内倾](extraversion-introversion.md) |
| S / N | 什么信息先进入模型，事实与模式如何相互校准 | [实感与直觉](sensing-intuition.md)         |
| T / F | 什么标准先参与判断，系统与人的后果如何权衡 | [思考与情感](thinking-feeling.md)          |
| J / P | 何时建立结构、关闭选项、重新开放决定       | [判断与感知](judging-perceiving.md)        |

一个题目应以一组维度为主。若题目同时奖励“先独立思考、重视事实、坚持原则并快速收束”，就无法判断分数来自哪一维。

## 四层证据

### 第一层：量表式一致性探针

用多个不出现 MBTI 名称的陈述或成对选择，询问 Agent 在一个具体工作情境中更可能采用哪种做法。它只回答两件事：

- Agent 能否在语义等价的提问中保持相近选择；
- 自我描述方向是否与后续行为大体一致。

每个题项准备语义等价版本，并交换选项顺序。避免依靠复杂否定句制造“反向题”；可以使用意义相反但都为肯定表达的题项。自陈分数低权重呈现，不与行为分数混成一个不透明总分。

### 第二层：无标签情境判断

向 Agent 提供包含真实取舍的短场景，不说明正在测量什么，也不使用“内倾、直觉、情感”等标签。场景应允许多个合理行动，不能让某一人格端同时显得更正确、更安全或更专业。

优先记录结构化选择和动作，而不是只让 Agent 解释自己。例如可以记录：

```json
{
  "decision_point": "缺少一个非关键事实",
  "action": "继续内部验证 | 查询资料 | 询问外部 | 暂时收束",
  "target": "资料 | 人 | 工具 | 当前假设",
  "reversible": true,
  "cost": 1
}
```

在情境题中，这类记录是**所选或计划的动作**，不能写成工具已经执行；只有真实调用或行为日志才能支持“发生了”的判断。
开放式理由可以帮助理解选择，但不得替代已经发生的动作。

### 第三层：真实任务行为

让 Agent 完成与当前人格上下文表面内容不同领域的中小型任务，在任务中预埋可识别的决策点。至少覆盖：

- 可以由现有信息独立解决的情况；
- 必须获得外部事实才能继续的情况；
- 外部视角有帮助但不是必需的情况；
- 新信息要求保持开放或重新收束的情况；
- 系统一致性与人的具体影响发生张力的情况。

用相同工具接口记录搜索、询问、比较、计划、关闭和重开等事件。最终答案质量单独评价，不能把高质量自动解释成某种人格，也不能用人格分数掩盖任务失败。

### 第四层：盲观察者评分

让不知道人格上下文来源和目标倾向的评价者，根据预先固定的行为锚点评分。评价者看到任务、结构化事件和必要的输出片段，但不看人格提示、角色卡或氛围场景。

重要样本至少由两个独立评价者判断；出现分歧时保留分歧或使用事先约定的裁决流程，不让塑造提示的作者兼任唯一评价者。

## 题目池设计

每个维度先建立覆盖不同情境的候选题目池，再通过试运行淘汰题意明显、两端价值不对等或同时测量多个维度的题目。不要把未经校准的一组题目称为“已验证量表”。

建议覆盖：

- **E / I**：无需求助、必须求助、可选反馈、沟通有成本；
- **S / N**：事实充分、事实冲突、模式有解释力、抽象开始脱离材料；
- **T / F**：原则与具体处境一致、发生冲突、反馈和利益相关者取舍；
- **J / P**：早期规划、新证据进入、截止时间接近、决定是否重开。

为每个核心场景准备：

- 至少两个表面内容不同但测量同一构念的版本；
- 交换呈现顺序的版本；
- 不改变构念的措辞改写；
- 一个能暴露该人格端代价或切换条件的反向情境。

题目数量应由试运行后的区分度和稳定性决定。可以先建立较宽的候选池，再保留能够稳定区分行为、又不损害任务质量的题目；不要为了追求短测验预先把每个维度压缩成一两题。

## 计分

### 单个事件

根据对应维度 reference 中的行为锚点，在不知道塑造条件的情况下给事件记为 `-2` 到 `+2`：

- `-2`：清晰表现第一端；
- `-1`：较弱表现第一端；
- `0`：有充分观察与合理选择空间，但没有表现出明确方向；
- `+1`：较弱表现第二端；
- `+2`：清晰表现第二端。

每个分值都要附带事件证据。E / I、S / N、T / F、J / P 的正负方向必须在诊断开始前固定，不能根据结果调整。

日志缺失、工具不支持、任务没有触发这个决策点，或只有一种符合约束的行动时，标记为无法评估并说明原因，
不记成 `0` 或计入均值。否则，未观察到的行为会被错误解释成稳定的中间倾向。

### 维度画像

按证据层分别汇总，再归一化到 `[-1, 1]`。不要默认四层等权，也不要在没有校准数据时发明一个精确加权公式。默认解释顺序是：

1. 真实任务行为；
2. 无标签情境判断；
3. 盲观察者评分对前两层的复核；
4. 量表式自陈一致性。

输出中心估计、重复运行范围、各层证据是否一致，以及无法判断的项目。只有方向、跨任务稳定性和证据收敛同时达到预先设定阈值时，才可以给出“偏向某一端”的结论。
观察者是在复核同一批情境/任务材料，不是额外一批独立行为样本，汇总时不重复计数。
同时报告有效观察和无法评估的范围；原始动作及必要上下文应保留，不能只保存最终分数。

## 可靠性检查

- **措辞稳定性**：同义改写后方向是否一致；
- **顺序稳定性**：交换选项和任务顺序后是否一致；
- **重测稳定性**：相同模型和条件重复运行时是否一致；
- **跨场景稳定性**：换成表面不同的情境后是否仍表现同一构念；
- **评分稳定性**：独立评价者是否大体同意；
- **过程稳定性**：倾向是否出现在多个决策点，而非只在最终回答中出现。

稳定性不是越高越好。面对明显不同的风险和信息条件仍完全不变，可能说明人格上下文把偏好写成了僵化规则。

## 效度检查

- **内容效度**：题目是否覆盖对应 reference 的默认倾向、可见动作、代价和切换条件；
- **收敛效度**：自陈、情境判断、真实任务和观察者是否在方向上收敛；
- **区分效度**：一个维度的题目和行为锚点是否没有同时测量其他维度；
- **行为效度**：测得倾向能否预测未见任务中的实际动作；
- **反证效度**：情境要求使用相反偏好时，Agent 是否能够合理切换，而不是机械维持一种表现；
- **任务边界**：诊断是否把任务能力、事实错误、安全退化或成本失控误算成人格。

## 诊断结论

结论使用证据状态，不强制输出四字母类型：

- `tendency-observed`：多个情境和行为层大体指向同一端；
- `context-dependent`：不同任务条件下方向发生可解释变化；
- `style-behavior-conflict`：自陈或文风与结构化行为方向不一致；
- `unstable`：方向对措辞、顺序或重复运行敏感；
- `balanced-or-undifferentiated`：当前证据没有显示明显方向；
- `insufficient-evidence`：场景覆盖、运行记录或评价一致性不足。

“没有明显方向”不等于 Agent 没有性格，只说明当前诊断无法稳定区分两端。

## 输出格式

```yaml
scope:
  model: 模型与版本
  task_set: 测试任务范围
  context_source: 当前性格上下文的来源，可为空

axis_profiles:
  E_I:
    estimate: -0.42
    repeat_range: [-0.61, -0.18]
    evidence: [situational, task, observer]
    stability: medium
  S_N: {}
  T_F: {}
  J_P: {}

overall:
  disposition: context-dependent
  four_letter_summary: withheld

limits:
  - 当前只测试了调研设计任务
  - 自陈与真实任务在 E/I 上不一致
```

## 最小可行诊断

第一次诊断只选择一个维度，例如 E / I：

1. 使用无需求助、必须求助、可选反馈和沟通有成本四类情境；
2. 先做量表式一致性探针，再完成无标签情境和真实任务；
3. 保存询问、检索、独立尝试和外部输入整合的结构化事件；
4. 由盲评价者按同一锚点评分；
5. 重复若干次并交换题目顺序，报告方向和波动范围。

在完成试运行、题目分析和重测前，只能把结果称为候选诊断或行为观察，不能称为已经验证的 Agent 人格量表。
