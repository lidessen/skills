# Personality workflow

## 找到有用的差异

用共同任务中的一个真实取舍说明为什么需要人格，例如更早寻求反馈，或先从实例而不是整体
模型理解问题。只挑相关维度和一种塑造方式；没有实际用途时不加人格，也不要求额外研究来
证明每次选择。

## 写成连贯倾向

让选中的维度共同回答：默认从哪里开始，注意和取舍怎样不同，什么证据或成本使它转向。
保留失衡的可能性与纠偏条件，不把优点堆成全能角色。人格是倾向，不是阶段脚本；用户任务
只有一个合理行动时就执行，不强行制造人格分歧。

## 交接材料

设计者至少交付两层内容：

1. **设计说明**：为什么需要这个差异，选了哪些维度，预期观察什么，什么反证会让设计重开。
2. **独立人格指令块**：适用范围、连贯的默认倾向、转向条件，以及沿用共同任务的边界。

推荐封装：

```text
[人格指令]
[一段独立、可执行的人格材料]

[共同任务]
[目标、已知事实、未知、交付标准和截止条件]

[可用材料与权限]
[工具、数据范围、workspace 和不可越过的边界]
```

人格指令只描述处理偏好和纠偏条件。不要把设计说明、观察指标、预期结论、隐藏验收条件
或本 skill 路径塞进指令块，也不要只发送类型名、人格卡或“按之前上下文做”。

## 应用与校正

用户要求应用时，把独立指令块和共同任务一起交给生产 Agent；材料交付与执行任务分别验收。材料只在本次
指定任务或明确角色范围内生效，任务变化后检查是否仍适用。用户要求切换或停止时替换旧材料，
不要逐层追加冲突人格。

用户要求验证效果时，观察真实的材料选择、比较、询问、决定与修订，不要求 Agent 自报人格。偏差出现时检查是
维度混杂、角色材料制造了额外目标，还是任务没有给偏好发挥空间；只修正原因，不堆形容词。

## 普通输出

```md
- 用途 / 目标 Agent：在哪里希望出现什么有用差异
- 选用偏好 / 塑造方式：实际采用的维度与方式
- 默认倾向与转向：一条连贯工作习惯及其纠偏
- 生效范围：本次任务或明确指定的持续角色
```

输出规模随任务而定；已有配置且用户要执行时，不必重复整张卡。

需要完整组合示例或检查交付材料时，才读取 [composition-examples.md](composition-examples.md)；
示例帮助检查独立性，不规定所有任务的路径。
