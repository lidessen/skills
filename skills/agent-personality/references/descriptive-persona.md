# 描述型角色塑造

## 读取时机

当需要用传统 persona prompt 直接定义 Agent 的人格时读取。

## 核心机制

描述型直接告诉 Agent 它是谁、具有什么性格，以及通常如何观察、思考和行动。控制关系是外显的：人格定义进入上下文，Agent 根据定义生成行为。

描述型容易生成、修改和复用，也最接近传统角色提示。它的风险是 Agent 只复现性格词汇和表达风格，没有在真实决策中形成一致倾向。

## 构造方法

从选中的人格维度提取以下内容：

只写与选中维度有关的部分，不为填满四项而添加人格。未选维度沿用任务所需的合理做法。

1. **关注对象**：它首先注意外部互动还是内部模型，事实还是模式。
2. **判断起点**：它先使用系统原则，还是先考虑人和价值的影响。
3. **行动节奏**：它何时计划、探索、询问、收束和修订。
4. **转向条件**：什么风险、证据或成本会使它使用相反偏好的能力。

把这些内容组织成一个连贯角色，而不是四段维度清单。例如：

```text
你是一名偏内倾的研究者。面对不确定问题时，你习惯先在内部形成一个
可检验的判断，再带着明确的问题进入沟通。你并不回避求助；当关键事实
只掌握在外部、错误代价较高或独立探索已经停滞时，你会及时询问。
```

## 边界

- 不只使用“安静、理性、富有想象力”等形容词；它们更容易塑造文风而非行为。
- 不把某一人格写成能力更强、信息更多、权限更高或道德上更好。
- 不把偏好写成禁令。相反端仍是必要时可调用的能力。
- 不要求 Agent 在输出中宣布、解释或证明自己的类型。
- 不暗示它必须得到与其他人格不同的答案；关注与取舍路径才是塑造对象。

需要可直接交给目标 Agent 的完整材料，读 [组合与使用示例](composition-examples.md)。人格正文与共同任务应一起送达，
不要把设计者使用的观察清单当成接收者必须表演的行为配额。

## 完成检查

- 描述覆盖选中维度的默认倾向与转向条件，没有无故补齐其他维度。
- 角色在多个决策点上能够生成行为，而不只是稳定语气。
- 人格维度、任务要求和安全边界没有混在一起。
- 描述型自身不要求角色准备；若任务明确需要组合，说明另一种材料的独立作用，不默认叠加。
